### 61. LeetCode 714

**Problem**

Given daily stock prices, maximize profit from any number of transactions, paying fee once per completed transaction. Hold at most one share at a time and sell before buying again.

**Examples**

- prices=[1,3,2,8,4,9], fee=2 → 8
- prices=[1,3,7,5,10,3], fee=3 → 6

**Constraints**

1 ≤ n ≤ 50000; 1 ≤ prices[i] < 50000; 0 ≤ fee < 50000

**Why this approach / key logic**

cash is maximum profit without a share; hold is maximum net profit with a share. Sell from old hold minus fee; buy from old cash. Initialize hold to minus first price.

**Locked strategy:** Two-state holding/cash DP; charge fee on sale (or purchase) exactly once.

**Evolution from previous solution:** BASE: each day can hold, buy, sell or rest, with paid transaction fee.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int maxProfit(int[] prices,int fee) {
        int cash=0,hold=-prices[0];
        for(int i=1;i<prices.length;i++) {
            int oldCash=cash;
            cash=Math.max(cash,hold+prices[i]-fee);
            hold=Math.max(hold,oldCash-prices[i]);
        }
        return cash;
    }
}
```

**Complexity:** O(n) time, O(1) space.

### 62. LeetCode 309

**Problem**

Maximize profit from unlimited stock trades holding at most one share, but after selling on day i you cannot buy on day i+1.

**Examples**

- [1,2,3,0,2] → 3
- [1] → 0

**Constraints**

1 ≤ n ≤ 5000; 0 ≤ prices[i] ≤ 1000

**Why this approach / key logic**

Separate nonholding into sold today and rest. Only previous rest can fund a buy; sold becomes eligible to buy after a rest day. Return maximum nonholding state.

**Locked strategy:** Track hold, sold, rest; buying can only come from prior rest.

**Evolution from previous solution:** Replace sale fee with post-sale cooldown state and forbidden immediate repurchase.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int maxProfit(int[] prices) {
        int hold=-prices[0],sold=Integer.MIN_VALUE/2,rest=0;
        for(int i=1;i<prices.length;i++) {
            int nextHold=Math.max(hold,rest-prices[i]);
            int nextSold=hold+prices[i];
            rest=Math.max(rest,sold);
            hold=nextHold;
            sold=nextSold;
        }
        return Math.max(rest,sold);
    }
}
```

**Complexity:** O(n) time, O(1) space.

### 63. LeetCode 123

**Problem**

Maximize stock trading profit using at most two completed buy-sell transactions. You cannot hold multiple shares simultaneously.

**Examples**

- [3,3,5,0,0,3,1,4] → 6
- [1,2,3,4,5] → 4
- [7,6,4,3,1] → 0

**Constraints**

1 ≤ n ≤ 100000; 0 ≤ prices[i] ≤ 100000

**Why this approach / key logic**

Four rolling action states store best profit after first buy, first sale, second buy, second sale. Update in reverse action order to consume previous-day states. Zero sale profits permit fewer transactions.

**Locked strategy:** Track 4 action states or dp[transactions][holding] for up to two sales.

**Evolution from previous solution:** Replace cooldown restriction with sale-count dimension and standard action transitions.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int maxProfit(int[] prices) {
        int buy1=-prices[0],buy2=-prices[0],sell1=0,sell2=0;
        for(int p:prices) {
            sell2=Math.max(sell2,buy2+p);
            buy2=Math.max(buy2,sell1-p);
            sell1=Math.max(sell1,buy1+p);
            buy1=Math.max(buy1,-p);
        }
        return sell2;
    }
}
```

**Complexity:** O(n) time, O(1) space.

### 64. LeetCode 188

**Problem**

Maximize profit using at most k buy-sell transactions, with at most one share held at a time.

**Examples**

- k=2, prices=[2,4,1] → 2
- k=2, prices=[3,2,6,5,0,3] → 7

**Constraints**

1 ≤ k ≤ 100; 1 ≤ n ≤ 1000; 0 ≤ prices[i] ≤ 1000

**Why this approach / key logic**

Generalize action states to arrays. Descend transaction index so buy[t] uses previous-day sell[t−1]. If k≥n/2, the limit cannot bind; sum positive adjacent gains.

**Locked strategy:** Generalize fixed 2 transactions to parameterized k states, handle k>=n/2 with unlimited-transactions optimization.

**Evolution from previous solution:** Replace fixed action slots with arrays by completed transaction budget and add unlimited-trade shortcut.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int maxProfit(int k,int[] prices) {
        int n=prices.length;
        if(k>=n/2) {
            int ans=0;
            for(int i=1;i<n;i++)ans+=Math.max(0,prices[i]-prices[i-1]);
            return ans;
        }
        int[] buy=new int[k+1],sell=new int[k+1];
        Arrays.fill(buy,-prices[0]);
        for(int p:prices)for(int t=k;t>=1;t--) {
            sell[t]=Math.max(sell[t],buy[t]+p);
            buy[t]=Math.max(buy[t],sell[t-1]-p);
        }
        return sell[k];
    }
}
```

**Complexity:** O(nk) time, O(k) space; unlimited shortcut O(n) time, O(1) space.

### 65. LeetCode 1027

**Problem**

Return length of longest subsequence whose consecutive values have the same difference, preserving original index order.

**Examples**

- [3,6,9,12] → 4
- [9,4,7,2,10] → 3

**Constraints**

2 ≤ n ≤ 1000; 0 ≤ nums[i] ≤ 500

**Why this approach / key logic**

dp[i][d] stores longest arithmetic chain ending at i with difference d. Offset differences by 500 to use bounded dense maps. A new pair has length two; extend earlier chains by one.

**Locked strategy:** Per-index map diff -> longest length, seeded at 2 for each pair.

**Evolution from previous solution:** BASE: equal difference extends earlier two-point arithmetic chain.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int longestArithSeqLength(int[] nums) {
        int n=nums.length,ans=2;
        int[][] dp=new int[n][1001];
        for(int i=0;i<n;i++)for(int j=0;j<i;j++) {
            int d=nums[i]-nums[j]+500;
            dp[i][d]=Math.max(dp[i][d],Math.max(2,dp[j][d]+1));
            ans=Math.max(ans,dp[i][d]);
        }
        return ans;
    }
}
```

**Complexity:** O(n²+nD) time, O(nD) space, D=1001 possible differences.

### 66. LeetCode 446

**Problem**

Count arithmetic subsequences of length at least three, distinguishing different index choices even if values match.

**Examples**

- [2,4,6,8,10] → 7
- [7,7,7,7,7] → 16

**Constraints**

1 ≤ n ≤ 1000; signed 32-bit values; answer fits signed int

**Why this approach / key logic**

Map each ending index and difference to number of arithmetic chains of length at least two. Extending any such chain adds a valid answer; the new pair contributes only to future states. Use long difference to avoid overflow.

**Locked strategy:** Per-index map diff -> number of length>=2 sequences; add previous counts to answer while adding previous counts+1 to current.

**Evolution from previous solution:** Replace max-length state with counting states and accumulate only extensions that reach length >=3.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int numberOfArithmeticSlices(int[] nums) {
        int n=nums.length;
        List<Map<Long,Long>> dp=new ArrayList<>();
        long ans=0;
        for(int i=0;i<n;i++) {
            Map<Long,Long> cur=new HashMap<>();
            for(int j=0;j<i;j++) {
                long d=(long)nums[i]-nums[j];
                long count=dp.get(j).getOrDefault(d,0L);
                ans+=count;
                cur.merge(d,count+1,Long::sum);
            }
            dp.add(cur);
        }
        return (int)ans;
    }
}
```

**Complexity:** O(n²) expected time, O(n²) space.

### 67. LeetCode 1911

**Problem**

Choose a subsequence maximizing alternating sum, adding the first selected element, subtracting the second, and alternating thereafter.

**Examples**

- [4,2,5,3] → 7
- [5,6,7,8] → 8

**Constraints**

1 ≤ n ≤ 100000; 1 ≤ nums[i] ≤ 100000

**Why this approach / key logic**

odd stores best sum after odd number of picks, even after even number. Skip or append with the appropriate sign. Use long for accumulated sums. Positive values allow the optimum to end with addition.

**Locked strategy:** Two rolling DP states by next sign (+/-) or parity of selected count.

**Evolution from previous solution:** BASE: alternating contribution sign determines two transition states.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public long maxAlternatingSum(int[] nums) {
        long even=0,odd=Long.MIN_VALUE/4;
        for(int x:nums) {
            long nextOdd=Math.max(odd,even+x);
            even=Math.max(even,odd-x);
            odd=nextOdd;
        }
        return Math.max(even,odd);
    }
}
```

**Complexity:** O(n) time, O(1) space.

### 68. LeetCode 376

**Problem**

Find longest subsequence whose consecutive differences strictly alternate positive and negative. Zero differences are not allowed; a single element is valid.

**Examples**

- [1,7,4,9,2,5] → 6
- [1,1,1] → 1

**Constraints**

1 ≤ n ≤ 1000; 0 ≤ nums[i] ≤ 1000

**Why this approach / key logic**

up and down track best lengths for opposite last difference signs. A rise can extend a down state, a fall an up state. Adjacent comparisons suffice because each monotone run can be replaced by its extreme without reducing future options.

**Locked strategy:** Track longest up/down subsequence ending in rise/fall and update on adjacent comparison.

**Evolution from previous solution:** Replace alternating sum objective with length, and sign-of-picked-element with direction of adjacent selected difference.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int wiggleMaxLength(int[] nums) {
        int up=1,down=1;
        for(int i=1;i<nums.length;i++) {
            if(nums[i]>nums[i-1])up=down+1;
            else if(nums[i]<nums[i-1])down=up+1;
        }
        return Math.max(up,down);
    }
}
```

**Complexity:** O(n) time, O(1) space.

### 69. LeetCode 1406

**Problem**

Alice and Bob alternately take one, two or three stones from the front of a row, earning their values (which may be negative). Both play optimally. Return Alice, Bob or Tie according to final score.

**Examples**

- [1,2,3,7] → Bob
- [1,2,3,-9] → Alice
- [1,2,3,6] → Tie

**Constraints**

1 ≤ n ≤ 50000; −1000 ≤ values ≤ 1000

**Why this approach / key logic**

dp[i] is best current-player score advantage on suffix i. For each legal take, maximize picked sum minus opponent advantage on remaining suffix. Keep only next three values using a circular array of four slots.

**Locked strategy:** Backward advantage DP: best of prefix-picked score minus opponent advantage.

**Evolution from previous solution:** BASE: zero-sum game transition using current gain minus opponent best.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public String stoneGameIII(int[] a) {
        int n=a.length;
        int[] dp=new int[4];
        for(int i=n-1;i>=0;i--) {
            int sum=0,best=Integer.MIN_VALUE;
            for(int x=1;x<=3&&i+x<=n;x++) {
                sum+=a[i+x-1];
                best=Math.max(best,sum-dp[(i+x)%4]);
            }
            dp[i%4]=best;
        }
        return dp[0]>0?"Alice":dp[0]<0?"Bob":"Tie";
    }
}
```

**Complexity:** O(n) time, O(1) space.

### 70. LeetCode 1140

**Problem**

Alice and Bob alternate taking first X remaining piles where 1≤X≤2M, initially M=1. Update M=max(M,X) after every move. Both maximize their own stones; return Alice’s total.

**Examples**

- [2,7,9,4,4] → 10
- [1,2,3,4,5,100] → 104

**Constraints**

1 ≤ n ≤ 100; 1 ≤ piles[i] ≤ 10000

**Why this approach / key logic**

Use suffix totals and memo(i,M) for current-player advantage. If all remaining piles fit, take them. Otherwise maximize picked total minus opponent advantage with updated M. Convert final advantage to Alice score via (total+advantage)/2.

**Locked strategy:** Memoized state (position,M), choose x in [1,2M], score current picked sum minus opponent advantage; use suffix totals.

**Evolution from previous solution:** Extend fixed take bound to state-dependent 2M and add M to memoization key.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    private int[] suffix;
    private Integer[][] memo;
    public int stoneGameII(int[] piles) {
        int n=piles.length;
        suffix=new int[n+1];
        memo=new Integer[n][n+1];
        for(int i=n-1;i>=0;i--)suffix[i]=suffix[i+1]+piles[i];
        return (suffix[0]+dfs(0,1))/2;
    }
    private int dfs(int i,int m) {
        int n=suffix.length-1;
        if(i+2*m>=n)return suffix[i];
        if(memo[i][m]!=null)return memo[i][m];
        int best=Integer.MIN_VALUE;
        for(int x=1;x<=2*m;x++)best=Math.max(best,suffix[i]-suffix[i+x]-dfs(i+x,Math.max(m,x)));
        return memo[i][m]=best;
    }
}
```

**Complexity:** O(n³) time, O(n²) space including recursion.

### 71. LeetCode 1690

**Problem**

Players alternately remove either endpoint stone, scoring the sum of stones remaining after removal. Alice maximizes final Alice−Bob difference, Bob minimizes it. Return difference under optimal play.

**Examples**

- [5,3,1,4,2] → 6
- [7,90,5,1,100,10,10,2] → 122

**Constraints**

2 ≤ n ≤ 1000; 1 ≤ stones[i] ≤ 1000

**Why this approach / key logic**

Prefix sums give remaining interval reward. dp[r] initially represents advantage on [l+1,r] while dp[r−1] already represents [l,r−1]. Iterate l descending and r ascending to roll the interval table.

**Locked strategy:** Interval advantage DP; choose left or right removal and gain sum of remaining interval.

**Evolution from previous solution:** BASE: remaining-sum boundary choices on intervals rather than suffix take-count games.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int stoneGameVII(int[] stones) {
        int n=stones.length;
        int[] pre=new int[n+1],dp=new int[n];
        for(int i=0;i<n;i++)pre[i+1]=pre[i]+stones[i];
        for(int l=n-2;l>=0;l--)for(int r=l+1;r<n;r++) {
            int left=pre[r+1]-pre[l+1]-dp[r];
            int right=pre[r]-pre[l]-dp[r-1];
            dp[r]=Math.max(left,right);
        }
        return dp[n-1];
    }
}
```

**Complexity:** O(n²) time, O(n) space.

### 72. LeetCode 688

**Problem**

A knight begins at (row,column) on an n×n board, chooses uniformly among eight possible knight moves at each step, and stops if it leaves the board. Return probability it remains after k moves.

**Examples**

- n=3,k=2,row=0,column=0 → 0.0625
- n=1,k=0,row=0,column=0 → 1

**Constraints**

1 ≤ n ≤ 25; 0 ≤ k ≤ 100; coordinates in [0,n−1]

**Why this approach / key logic**

Forward probability mass at each cell is distributed equally among eight destinations. Discard mass leaving board; sum remaining mass after k steps.

**Locked strategy:** Move-step DP over 8 knight moves, 2D probability grids rolled per step.

**Evolution from previous solution:** BASE: distribute state probability evenly over next moves, discarding off-board outcomes.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public double knightProbability(int n,int k,int row,int column) {
        int[][] moves= {
            {
                1,2
            }
            , {
                2,1
            }
            , {
                -1,2
            }
            , {
                -2,1
            }
            , {
                1,-2
            }
            , {
                2,-1
            }
            , {
                -1,-2
            }
            , {
                -2,-1
            }
        }
        ;
        double[][] dp=new double[n][n];
        dp[row][column]=1;
        for(int step=0;step<k;step++) {
            double[][] next=new double[n][n];
            for(int r=0;r<n;r++)for(int c=0;c<n;c++)if(dp[r][c]!=0)for(int[] m:moves) {
                int x=r+m[0],y=c+m[1];
                if(x>=0&&x<n&&y>=0&&y<n)next[x][y]+=dp[r][c]/8;
            }
            dp=next;
        }
        double ans=0;
        for(double[] line:dp)for(double p:line)ans+=p;
        return ans;
    }
}
```

**Complexity:** O(kn²+n²) time, O(n²) space.

### 73. LeetCode 837

**Problem**

Alice starts with zero points and draws an independent uniform integer in [1,maxPts] while her score is below k. Return probability her final score is at most n.

**Examples**

- n=10,k=1,maxPts=10 → 1
- n=6,k=1,maxPts=10 → 0.6
- n=21,k=17,maxPts=10 → approximately 0.73278

**Constraints**

0 ≤ k ≤ n ≤ 10000; 1 ≤ maxPts ≤ 10000

**Why this approach / key logic**

dp[i] is probability of reaching score i. Maintain a rolling sum of prior active scores in [i−maxPts,i−1] that are below k. Terminal scores add to answer rather than propagating. If n≥k−1+maxPts or k=0, success is certain.

**Locked strategy:** 1D forward probability DP with sliding sum of last maxPts active states; stop propagation at threshold k.

**Evolution from previous solution:** Replace 2D coordinate transitions with scalar score and rolling-window probability accumulation.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public double new21Game(int n,int k,int maxPts) {
        if(k==0||n>=k-1+maxPts)return 1;
        double[] dp=new double[n+1];
        dp[0]=1;
        double window=1,ans=0;
        for(int i=1;i<=n;i++) {
            dp[i]=window/maxPts;
            if(i<k)window+=dp[i];
            else ans+=dp[i];
            int old=i-maxPts;
            if(old>=0&&old<k)window-=dp[old];
        }
        return ans;
    }
```

**Problem**

```java
import java.util.*;

class Solution {
    private int[][] counts;
    private int[] memo;
    private String target;
    private int full;
    public int minStickers(String[] stickers,String target) {
        this.target=target;
        int t=target.length();
        full=(1<<t)-1;
        memo=new int[1<<t];
        Arrays.fill(memo,-2);
        memo[full]=0;
        counts=new int[stickers.length][26];
        for(int i=0;i<stickers.length;i++)for(char c:stickers[i].toCharArray())counts[i][c-'a']++;
        return dfs(0);
    }
    private int dfs(int mask) {
        if(memo[mask]!=-2)return memo[mask];
        int first=Integer.numberOfTrailingZeros(full^mask),best=target.length()+1;
        for(int[] sticker:counts) {
            if(sticker[target.charAt(first)-'a']==0)continue;

            for(int j=0;j<target.length();j++) {
                int c=target.charAt(j)-'a';
                if((next&(1<<j))==0&&remain[c]>0) {
                    remain[c]--;
                    next|=1<<j;
                }
            }
            int sub=dfs(next);
            if(sub>=0)best=Math.min(best,sub+1);
        }
        return memo[mask]=best>target.length()?-1:best;
```

### 77. LeetCode 1799

**Problem**

Given 2n positive integers, perform n operations, choosing two unused numbers at operation i and earning i times their greatest common divisor. Maximize total score.

**Examples**

- [1,2] → 1
- [3,4,6,8] → 11
- [1,2,3,4,5,6] → 14

**Constraints**

1 ≤ n ≤ 7; nums.length=2n; 1 ≤ nums[i] ≤ 10^6

**Why this approach / key logic**

Mask records used indices; operation number is bitCount(mask)/2+1. Try every unused pair, not just pairs containing the first unused index: operation weights make pair order significant. Precompute gcd and memoize best future score.

**Locked strategy:** Memoize used-index bitmask; choose unused pair, score operationNumber*gcd(pair) plus next state.

**Evolution from previous solution:** Replace monotone coverage with paired unused-index selection, optimize weighted accumulation instead of minimum team size.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    private int[][] gcd;
    private int[] memo;
    private int n,full;
    public int maxScore(int[] nums) {
        n=nums.length;
        full=(1<<n)-1;
        gcd=new int[n][n];
        for(int i=0;i<n;i++)for(int j=i+1;j<n;j++)gcd[i][j]=gcdOf(nums[i],nums[j]);
        memo=new int[1<<n];
        Arrays.fill(memo,-1);
        memo[full]=0;
        return dfs(0);
    }
    private int dfs(int mask) {
        if(memo[mask]>=0)return memo[mask];
        int op=Integer.bitCount(mask)/2+1,best=0;
        for(int i=0;i<n;i++)if((mask&(1<<i))==0)for(int j=i+1;j<n;j++)if((mask&(1<<j))==0)best=Math.max(best,op*gcd[i][j]+dfs(mask|(1<<i)|(1<<j)));
        return memo[mask]=best;
    }
    private int gcdOf(int a,int b) {
        while(b!=0) {
            int t=a%b;
            a=b;
            b=t;
        }
        return a;
    }
}
```

```java
            int pair=(s.charAt(i-1)-'0')*10+s.charAt(i)-'0';
            if(pair>=10&&pair<=26)curr+=prev2;
            prev2=prev1;
            prev1=curr;
        }
        return prev1;
    }
}
```

**Complexity:** O(n) time, O(1) space.

### 86. LeetCode 639

**Problem**

Decode a string of digits and * using 1→A through 26→Z. Each * independently represents any digit 1..9. Count all valid decodings over all wildcard assignments, modulo 1,000,000,007.

**Examples**

- * → 9
- 1* → 18
- ** → 96

**Constraints**

1 ≤ s.length ≤ 10^5; digits and * only

**Why this approach / key logic**

Reuse rolling prefix recurrence. Replace single/pair validity booleans with counts: ** has 15 valid pairs (11..19,21..26), *d has 2 for d≤6 else 1, d* has 9 for 1 and 6 for 2. Multiply prefix counts by token multiplicities using long.

**Locked strategy:** Reuse two-previous-state recurrence; replace boolean single/pair validity with multiplicity counts (up to 9 or 15), modulo 1e9+7.

**Evolution from previous solution:** Generalize valid-token tests to count multiple wildcard interpretations and apply modular arithmetic.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    private static final long MOD=1000000007L;
    public int numDecodings(String s) {
        long prev2=1,prev1=single(s.charAt(0));
        for(int i=1;i<s.length();i++) {
            long curr=(prev1*single(s.charAt(i))+prev2*pair(s.charAt(i-1),s.charAt(i)))%MOD;
            prev2=prev1;
            prev1=curr;
        }
        return (int)prev1;
    }
    private int single(char c) {
        return c=='*'?9:c=='0'?0:1;
    }
    private int pair(char a,char b) {
        if(a=='*'&&b=='*')return 15;
        if(a=='*')return b<='6'?2:1;
        if(b=='*')return a=='1'?9:a=='2'?6:0;
        int value=(a-'0')*10+b-'0';
        return value>=10&&value<=26?1:0;
    }
}
```

**Complexity:** O(n) time, O(1) space.

### 87. LeetCode 115

**Problem**

Count the distinct index selections from source string s that form target t in order. Different choices of indices count separately even if selected characters are identical.

**Examples**

- s=rabbbit,t=rabbit → 3
- s=babgbag,t=bag → 5

**Constraints**

1 ≤ s.length,t.length ≤ 1000; English letters; answer fits signed int

**Why this approach / key logic**

dp[j] counts ways to form first j target characters from processed source prefix. Empty target has one way. Skipping leaves dp[j] unchanged; matching source character adds dp[j−1]. Descend j so a source character cannot be used twice. Cap intermediate counts at Integer.MAX_VALUE: transitions only add nonnegative values, so saturation cannot change a representable final result.

**Locked strategy:** 1D rolling source-prefix vs target-prefix counting; descend target indices to prevent reusing source char.

**Evolution from previous solution:** BASE: skip current source character or consume it when matching target next symbol.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int numDistinct(String s,String t) {
        int n=t.length();
        if(n>s.length())return 0;
        int[] dp=new int[n+1];
        dp[0]=1;
        for(int i=0;i<s.length();i++)for(int j=Math.min(n,i+1);j>=1;j--)if(s.charAt(i)==t.charAt(j-1))dp[j]=(int)Math.min(Integer.MAX_VALUE,(long)dp[j]+dp[j-1]);
        return dp[n];
    }
}
```

**Complexity:** O(mn) time, O(n) space, m=source length, n=target length.

### 88. LeetCode 940

**Problem**

Count distinct nonempty subsequence strings of a lowercase string, identifying subsequences with identical contents even if their index selections differ. Return modulo 1,000,000,007.

**Examples**

- abc → 7
- aba → 6
- aaa → 3

**Constraints**

1 ≤ s.length ≤ 2000; lowercase letters

**Why this approach / key logic**

total includes empty subsequence. Appending new character to all old subsequences doubles total, but if character appeared before, some new strings already exist. Subtract total immediately before previous occurrence of that character; save old total for next occurrence. Remove empty at end.

**Locked strategy:** Keep total ways including empty and previous prefix total for each ending symbol; double then subtract duplicates modulo MOD.

**Evolution from previous solution:** BASE: compensate for identical sequences introduced by recurring final character.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int distinctSubseqII(String s) {
        long mod=1000000007L,total=1;
        long[] last=new long[26];
        for(int i=0;i<s.length();i++) {
            int c=s.charAt(i)-'a';
            long old=total;
            total=(2*total-last[c]+mod)%mod;
            last[c]=old;
        }
        return (int)((total-1+mod)%mod);
    }
}
```

### 89. LeetCode 174

**Problem**

A knight starts in top-left of a dungeon and moves only right or down to rescue princess at bottom-right. Each cell changes health by its signed value, including both endpoints. Health must remain at least 1 at all times. Return minimum starting health.

**Examples**

- [[-2,-3,3],[-5,-10,1],[10,30,-5]] → 7
- [[0]] → 1
- [[-5]] → 6

**Constraints**

1 ≤ rows,cols ≤ 200; −1000 ≤ cell value ≤ 1000

**Why this approach / key logic**

Work backward. need[r][c] is minimum health before entering cell to survive until destination. Choose successor requiring less health, subtract current cell value, clamp to at least 1. Roll rows right-to-left; sentinel neighbors are impossible except one virtual successor of destination requiring 1.

**Locked strategy:** Reverse DP from destination using required-health invariant max(1,min(successorNeed)-cellValue).

**Evolution from previous solution:** BASE: optimize required starting resource backward instead of accumulating path reward forward.

**Java 21 solution**

```java
import java.util.*;

class Solution {
    public int calculateMinimumHP(int[][] dungeon) {
        int rows=dungeon.length,cols=dungeon[0].length;
        int[] dp=new int[cols+1];
        Arrays.fill(dp,Integer.MAX_VALUE);
        dp[cols-1]=1;
        for(int r=rows-1;r>=0;r--)for(int c=cols-1;c>=0;c--) {
            int need=Math.min(dp[c],dp[c+1]);
            dp[c]=Math.max(1,need-dungeon[r][c]);
        }
        return dp[0];
    }
}
```

**Complexity:** O(RC) time, O(C) space.

## Subpattern L1: One-pass payload aggregation

**When to Apply:** A linked sequence carries digits or delimiters, and an answer can be accumulated without mutating links.

**Basic Java Code Snippet:**

```java
int value = 0;
for (ListNode node = head; node != null; node = node.next) {
    value = value * base + node.val; // base supplied by constraints
}
```

**Core Logic:** The accumulator represents the entire prefix already consumed. Multiplying by the radix shifts that prefix one place before incorporating the next digit.

**Questions Covered:** 1290


### LeetCode 1290

**Question:**

Given a nonempty singly linked list of binary digits, with the most significant bit at the head, return the integer represented by the entire sequence.

**Examples:**

- [1,0,1] → 5
- [0] → 0
- [1,1,0] → 6

**Constraints:**

1–30 nodes; values are 0 or 1.

**Why This Subpattern Applies:**

Binary digits arranged from head to tail; fold `value = 2*value + bit` in one forward traversal; O(n)/O(1). The accumulator represents the entire prefix already consumed.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int getDecimalValue(ListNode head) {
        int value = 0;
        for (; head != null; head = head.next) value = value * 2 + head.val;
        return value;
    }
}
```

**Key Logic:**

Each update shifts the existing binary prefix left by one bit and adds the current bit. Leading zeroes are harmless.

**Time Complexity:** O(n), one scan.

**Space Complexity:** O(1), scalar accumulator.

## Subpattern L2: In-place contiguous segment reversal

**When to Apply:** A contiguous set of `next` edges must reverse while node identity and O(1) auxiliary space are preserved.

**Basic Java Code Snippet:**

```java
ListNode prev = null, curr = head;
while (curr != null) {
    ListNode next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
}
// prev is the head of the reversed segment.
```

**Core Logic:** At each iteration prev heads the reversed prefix and curr heads the unread suffix. Save the original successor before redirecting the current edge.

**Questions Covered:** 206, 92


### LeetCode 206

**Question:**

Given the head of a singly linked list, reverse its links and return the new head. An empty list remains empty; reuse the original nodes.

**Examples:**

- [1,2,3] → [3,2,1]
- [1] → [1]
- [] → []

**Constraints:**

0–5000 nodes; -5000 ≤ value ≤ 5000.

**Why This Subpattern Applies:**

Reverse all `next` pointers iteratively with `prev/current/next`; O(n)/O(1). At each iteration prev heads the reversed prefix and curr heads the unread suffix.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        ListNode prev = null;
        while (head != null) {
            ListNode next = head.next;
            head.next = prev;
            prev = head;
            head = next;
        }
        return prev;
    }
}
```

**Key Logic:**

Save the successor before overwriting next. The reversed prefix ends at the original head, and prev is its current head.

**Time Complexity:** O(n), each link visited once.

**Space Complexity:** O(1), three references.

### LeetCode 92

**Question:**

Reverse the nodes from position left through right inclusive (positions start at one), leaving all other nodes in their original order. Return the possibly changed head.

**Examples:**

- [1,2,3,4,5], 2,4 → [1,4,3,2,5]
- [5],1,1 → [5]
- [1,2],1,2 → [2,1]

**Constraints:**

1 ≤ n ≤ 500; -500 ≤ value ≤ 500; 1 ≤ left ≤ right ≤ n.

**Why This Subpattern Applies:**

Reverse just 1-indexed interval `[left,right]` in-place using dummy sentinel, preceding node and head-insertion; O(n)/O(1). At each iteration prev heads the reversed prefix and curr heads the unread suffix.

**Connection to Previous Solution:**

From LeetCode 206: Replace the whole-list prev/current loop with a dummy and fixed predecessor at left−1. Keep the original interval head as tail; repeat `move = tail.next; tail.next = move.next; move.next = before.next; before.next = move` exactly right−left times. The outside prefix and suffix remain connected.

**Java Solution:**

```java
class Solution {
    public ListNode reverseBetween(ListNode head, int left, int right) {
        ListNode dummy = new ListNode(0, head), before = dummy;
        for (int i = 1; i < left; i++) before = before.next;
        ListNode tail = before.next;
        for (int i = left; i < right; i++) {
            ListNode move = tail.next;
            tail.next = move.next;
            move.next = before.next;
            before.next = move;
        }
        return dummy.next;
    }
}
```

**Key Logic:**

The sentinel locates the predecessor even when left is one. Keep the original interval head as its tail; repeatedly extract its successor and insert it at the interval front.

**Time Complexity:** O(n), locate and reverse interval.

**Space Complexity:** O(1), sentinel and cursors.

## Subpattern L3: Local group reversal

**When to Apply:** Swap actual nodes, not just values; the operation repeats on bounded consecutive groups.

**Basic Java Code Snippet:**

```java
// before precedes a complete group of size k; verify before calling.
ListNode first = before.next, after = first;
for (int i = 0; i < k; i++) after = after.next;
ListNode prev = after, curr = first;
while (curr != after) {
    ListNode next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
}
before.next = prev;
before = first;
```

**Core Logic:** A group boundary remains anchored by before. Starting prev at the successor after the group makes the reversed tail reconnect automatically; only complete groups should be processed.

**Questions Covered:** 24, 25


### LeetCode 24

**Question:**

Swap every adjacent pair of nodes in a singly linked list and return its head. Do not change node values; an unpaired final node stays in place.

**Examples:**

- [1,2,3,4] → [2,1,4,3]
- [1,2,3] → [2,1,3]
- [] → []

**Constraints:**

0–100 nodes; 0 ≤ value ≤ 100.

**Why This Subpattern Applies:**

Reverse adjacent pairs with dummy anchor and three pointer rewires per pair; O(n)/O(1). A group boundary remains anchored by before.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public ListNode swapPairs(ListNode head) {
        ListNode dummy = new ListNode(0, head), before = dummy;
        while (before.next != null && before.next.next != null) {
            ListNode a = before.next, b = a.next;
            a.next = b.next;
            b.next = a;
            before.next = b;
            before = a;
        }
        return dummy.next;
    }
}
```

**Key Logic:**

Before each pair, before points to the preceding node. Reconnect a to the suffix, b to a, and before to b; advance before to a.

**Time Complexity:** O(n), one visit per pair.

**Space Complexity:** O(1), constant pointers.

### LeetCode 25

**Question:**

Reverse each consecutive group of k nodes, using node rewiring rather than modifying values. If fewer than k nodes remain at the end, preserve their order. Return the new head.

**Examples:**

- [1,2,3,4,5],2 → [2,1,4,3,5]
- same list,3 → [3,2,1,4,5]
- [1],1 → [1]

**Constraints:**

1 ≤ k ≤ n ≤ 5000; 0 ≤ value ≤ 1000.

**Why This Subpattern Applies:**

Reverse only *complete* groups of `k` by finding kth node, reversing group and reconnecting; O(n)/O(1). A group boundary remains anchored by before.

**Connection to Previous Solution:**

From LeetCode 24: Replace the two-node `a/b` swap with a k-step lookahead from before. Seed `prev = after`, reverse links until `curr == after`, reconnect `before.next = kth`, then set before to the old first node. An incomplete group is returned unchanged.

**Java Solution:**

```java
class Solution {
    public ListNode reverseKGroup(ListNode head, int k) {
        ListNode dummy = new ListNode(0, head), before = dummy;
        while (true) {
            ListNode kth = before;
            for (int i = 0; i < k && kth != null; i++) kth = kth.next;
            if (kth == null) return dummy.next;
            ListNode after = kth.next, curr = before.next, prev = after;
            ListNode oldFirst = curr;
            while (curr != after) {
                ListNode next = curr.next;
                curr.next = prev;
                prev = curr;
                curr = next;
            }
            before.next = kth;
            before = oldFirst;
        }
    }
}
```

**Key Logic:**

First verify k nodes exist. Seed prev with the group successor so reversal automatically attaches the suffix. The old first node becomes the next group predecessor.

**Time Complexity:** O(n), at most two visits per group.

**Space Complexity:** O(1), constant pointers.

## Subpattern L4: Fast/slow midpoint + second-half reversal

**When to Apply:** A middle position or symmetric nodes are needed without array conversion.

**Basic Java Code Snippet:**

```java
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
// slow is middle; optionally reverse/compare second half.
```

**Core Logic:** The two-to-one speed ratio identifies a midpoint without length counting. For symmetric comparisons, reverse only the second half to align pairs.

**Questions Covered:** 876, 2095, 234, 2130


### LeetCode 876

**Question:**

Return the actual middle node of a nonempty singly linked list. If there are two middle nodes, return the second one. The returned node includes its remaining suffix.

**Examples:**

- [1,2,3,4,5] → [3,4,5]
- [1,2,3,4,5,6] → [4,5,6]
- [1] → [1]

**Constraints:**

1–100 nodes; 1 ≤ value ≤ 100.

**Why This Subpattern Applies:**

Find second middle of singly linked list with slow/fast cursors; O(n)/O(1). The two-to-one speed ratio identifies a midpoint without length counting.

**Connection to Previous Solution:**

**Java Solution:**

```java
class Solution {
    public ListNode middleNode(ListNode head) {
        ListNode slow = head, fast = head;
```

**Key Logic:**

Fast moves twice as far as slow. When fast reaches the end, slow has moved floor(n/2) positions from head.

**Time Complexity:** O(n), fast traverses list.

### LeetCode 2095

**Question:**

Delete the node at zero-based index floor(n/2) and return the head. For a one-node list, the result is empty.

**Examples:**

```java
class Solution {
    public ListNode deleteMiddle(ListNode head) {
```

### LeetCode 234

**Question:**

Determine whether the sequence of values in a singly linked list is a palindrome, meaning it reads identically in either direction. Return a boolean; target linear time and constant auxiliary memory.

**Examples:**

- [1,2,2,1] → true
- [1,2] → false
- [1,2,1] → true

**Constraints:**

1–100000 nodes; 0 ≤ value ≤ 9.

**Why This Subpattern Applies:**

Test palindrome by finding midpoint, reversing the second half, pairwise comparing, then optionally restoring links; O(n)/O(1). The two-to-one speed ratio identifies a midpoint without length counting.

**Connection to Previous Solution:**

From LeetCode 2095: Replace predecessor tracking/deletion with a midpoint loop that stops at the first-half tail (`fast.next != null && fast.next.next != null`). Reverse `slow.next`, compare aligned values, and restore the reversed segment before returning the boolean.

**Java Solution:**

```java
class Solution {
    public boolean isPalindrome(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        ListNode second = reverse(slow.next);
        boolean equal = true;
        for (ListNode a = head, b = second; b != null; a = a.next, b = b.next) {
            if (a.val != b.val) { equal = false; break; }
        }
        slow.next = reverse(second);
        return equal;
    }
    private ListNode reverse(ListNode p) {
        ListNode prev = null;
        while (p != null) {
            ListNode next = p.next;
            p.next = prev;
            prev = p;
            p = next;
        }
        return prev;
    }
}
```

**Key Logic:**

Find the end of the first half, reverse the following nodes and compare until that reversed half ends. Restore even after a mismatch so the caller retains the original list.

**Time Complexity:** O(n), midpoint, reversal, comparison and restoration.

**Space Complexity:** O(1), constant pointers.

### LeetCode 2130

**Question:**

For an even-length list of n nodes, node i and node n-1-i are twins for 0 ≤ i < n/2. Return the largest sum of values of any twin pair.

**Examples:**

- [5,4,2,1] → 6
- [4,2,2,3] → 7
- [1,100000] → 100001

**Constraints:**

Even n, 2–100000 nodes; 1 ≤ value ≤ 100000.

**Why This Subpattern Applies:**

Compute maximum twin sum on even-length list by reversing second half and scanning paired halves; O(n)/O(1). The two-to-one speed ratio identifies a midpoint without length counting.

**Connection to Previous Solution:**

From LeetCode 234: Retain the same midpoint, reverse helper and restoration as LC 234. Replace the mismatch branch with `best = Math.max(best, a.val + b.val)` and return best; the list length is guaranteed even.

**Java Solution:**

```java
class Solution {
    public int pairSum(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        ListNode second = reverse(slow.next);
        int best = 0;
        for (ListNode a = head, b = second; b != null; a = a.next, b = b.next)
            best = Math.max(best, a.val + b.val);
        slow.next = reverse(second);
        return best;
    }
    private ListNode reverse(ListNode p) {
        ListNode prev = null;
        while (p != null) {
            ListNode next = p.next;
            p.next = prev;
            prev = p;
            p = next;
        }
        return prev;
    }
}
```

**Key Logic:**

Reverse the second half to align each twin with its partner from the head. Track the maximum sum and restore the original links.

**Time Complexity:** O(n), half reversal and scan.

**Space Complexity:** O(1), constant pointers.

## Subpattern L5: Floyd cycle detection and entry

**When to Apply:** Nodes may revisit a predecessor and only O(1) extra memory is allowed.

**Basic Java Code Snippet:**

```java
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) { /* meeting inside cycle */ break; }
}
```

**Core Logic:** Acyclic traversal eventually reaches null; in a cycle, the faster cursor gains one position per iteration. A meeting proves a cycle, and a second phase can locate its entrance.

**Questions Covered:** 141, 142


### LeetCode 141

**Question:**

Return whether a linked list contains a cycle: following next repeatedly can revisit the same node. The judge may describe a tail connection using pos, but pos is not an argument. Do not modify the list.

**Examples:**

- [3,2,0,-4], pos=1 → true
- [1,2], pos=0 → true
- [1], pos=-1 → false

**Constraints:**

0–10000 nodes; -100000 ≤ value ≤ 100000; pos is -1 or a valid index.

**Why This Subpattern Applies:**

Detect cycle via slow/fast identity meeting; O(n)/O(1). Acyclic traversal eventually reaches null; in a cycle, the faster cursor gains one position per iteration.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public boolean hasCycle(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) return true;
        }
        return false;
    }
}
```

**Key Logic:**

If acyclic, fast reaches null. Within a cycle the relative distance changes by one each step, so the references must meet. Compare references, not values.

**Time Complexity:** O(n), meeting or termination.

**Space Complexity:** O(1), two pointers.

### LeetCode 142

**Question:**

Return the actual node where the cycle begins, or null if there is no cycle. The judge describes the tail link using pos, which is not a method argument. Preserve the list.

**Examples:**

- [3,2,0,-4], pos=1 → node at index 1
- [1,2], pos=0 → head
- [1], pos=-1 → null

**Constraints:**

0–10000 nodes; -100000 ≤ value ≤ 100000; pos is -1 or valid index.

**Why This Subpattern Applies:**

Locate cycle entrance after detecting a meeting; O(n)/O(1). Acyclic traversal eventually reaches null; in a cycle, the faster cursor gains one position per iteration.

**Connection to Previous Solution:**

From LeetCode 141: Keep the Floyd meeting test. Instead of returning true, reset `slow = head` and advance both pointers one edge at a time until their references agree. Replace false with null for acyclic lists.

**Java Solution:**

```java
class Solution {
    public ListNode detectCycle(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {
                slow = head;
                while (slow != fast) { slow = slow.next; fast = fast.next; }
                return slow;
            }
        }
        return null;
    }
}
```

**Key Logic:**

At a meeting, the distance from head to entry equals the distance from meeting to entry modulo cycle length. Reset slow to head and move both one step until they meet at entry.

**Time Complexity:** O(n), two Floyd phases.

**Space Complexity:** O(1), two pointers.

## Subpattern L6: Sorted-list merging as primitive

**When to Apply:** Two sorted runs can be consumed by selecting smaller front node and relinking, without copying payloads.

**Basic Java Code Snippet:**

```java
ListNode dummy = new ListNode(), tail = dummy;
while (a != null && b != null) {
    if (a.val <= b.val) { tail.next = a; a = a.next; }
    else { tail.next = b; b = b.next; }
    tail = tail.next;
}
tail.next = a != null ? a : b;
```

**Core Logic:** The output prefix remains sorted and contains all consumed nodes. The smallest remaining value must be at the head of one of the sorted inputs.

**Questions Covered:** 21, 148


### LeetCode 21

**Question:**

Merge two nondecreasing singly linked lists into one nondecreasing list by splicing together their original nodes. Return the merged head; either input can be empty.

**Examples:**

- [1,2,4], [1,3,4] → [1,1,2,3,4]
- [],[] → []
- [],[0] → [0]

**Constraints:**

0–50 nodes per list; -100 ≤ value ≤ 100; both sorted nondecreasing.

**Why This Subpattern Applies:**

Merge two sorted lists with dummy tail, attaching smaller head until one list ends; O(n+m)/O(1). The output prefix remains sorted and contains all consumed nodes.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public ListNode mergeTwoLists(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(), tail = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) { tail.next = a; a = a.next; }
            else { tail.next = b; b = b.next; }
            tail = tail.next;
        }
        tail.next = a != null ? a : b;
        return dummy.next;
    }
}
```

**Key Logic:**

The smaller front is the smallest remaining value. Append it to the sorted prefix, then attach the entire remaining run when one input ends.

**Time Complexity:** O(n+m), each node consumed once.

**Space Complexity:** O(1), sentinel and cursors.

### LeetCode 148

**Question:**

Sort a singly linked list in ascending order and return its head. The required efficient approach runs in O(n log n); the follow-up requests constant auxiliary space.

**Examples:**

- [4,2,1,3] → [1,2,3,4]
- [-1,5,3,4,0] → [-1,0,3,4,5]
- [] → []

**Constraints:**

0–50000 nodes; -100000 ≤ value ≤ 100000.

**Why This Subpattern Applies:**

Sort list in O(n log n) time using linked-list merge sort; split by middle and reuse two-list merge; O(log n) recursion. The output prefix remains sorted and contains all consumed nodes.

**Connection to Previous Solution:**

From LeetCode 21: Extract LC 21’s merge loop into a helper. Add a base case for zero/one node, find the first-half tail using fast=head.next, sever its next, recursively sort both halves, then pass them into merge.

**Java Solution:**

```java
class Solution {
    public ListNode sortList(ListNode head) {
        if (head == null || head.next == null) return head;
        ListNode slow = head, fast = head.next;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        ListNode right = slow.next;
        slow.next = null;
        return merge(sortList(head), sortList(right));
    }
    private ListNode merge(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(), tail = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) { tail.next = a; a = a.next; }
            else { tail.next = b; b = b.next; }
            tail = tail.next;
        }
        tail.next = a != null ? a : b;
        return dummy.next;
    }
}
```

**Key Logic:**

Split into two nonempty halves by stopping slow at the first half tail and severing its next. Recursively sort each half and merge using the same front-selection rule. This follows the locked recursive strategy.

**Time Complexity:** O(n log n), linear merging per level.

**Space Complexity:** O(log n), recursive call stack; bottom-up variant meets constant-space follow-up.

```java
            p.next.random = p.random == null ? null : p.random.next;
        Node result = head.next;
        for (Node p = head; p != null; ) {
            Node copy = p.next;
            p.next = copy.next;
            copy.next = p.next == null ? null : p.next.next;
            p = p.next;
        }
        return result;
    }
}
```

**Key Logic:**

Insert each copy immediately after its original. A random target's copy is therefore target.next. Detach both chains in the final scan, restoring original next links.

**Time Complexity:** O(n), three scans.

**Space Complexity:** O(1) auxiliary, O(n) new output nodes.

## Subpattern L17: Doubly linked LRU order + hash index

```java
        int key, value;
        Entry prev, next;

    private final int capacity;
    public LRUCache(int capacity) {

    }
    private void detach(Entry e) { e.prev.next = e.next; e.next.prev = e.prev; }
    private void append(Entry e) {
        e.prev = tail.prev; e.next = tail; tail.prev.next = e; tail.prev = e;
```

## Subpattern L18: Frequency buckets with LRU tie-breaking

**When to Apply:** Evict lowest access frequency, breaking ties by least-recent use.

**Basic Java Code Snippet:**

```java
class LFUCache {
    private static class Entry {
        int key, value, freq = 1;
        Entry prev, next;
        Entry(int k, int v) { key = k; value = v; }
    }
    private static class Bucket {
        final Entry head = new Entry(0,0), tail = new Entry(0,0);
        Bucket() { head.next = tail; tail.prev = head; }
        void add(Entry e) { e.prev = tail.prev; e.next = tail; tail.prev.next = e; tail.prev = e; }
        void remove(Entry e) { e.prev.next = e.next; e.next.prev = e.prev; }
        boolean empty() { return head.next == tail; }
    }
    private final java.util.Map<Integer,Entry> entries = new java.util.HashMap<>();
    private final java.util.Map<Integer,Bucket> buckets = new java.util.HashMap<>();
    private final int capacity;
    private int minFrequency;
    public LFUCache(int capacity) { this.capacity = capacity; }
    private void touch(Entry e) {
        int f = e.freq;
        Bucket old = buckets.get(f); old.remove(e);
        if (old.empty()) { buckets.remove(f); if (minFrequency == f) minFrequency++; }
        e.freq++;
        buckets.computeIfAbsent(e.freq, ignored -> new Bucket()).add(e);
    }
    public int get(int key) {
        Entry e = entries.get(key);
        if (e == null) return -1;
        touch(e); return e.value;
    }
    public void put(int key, int value) {
        if (capacity == 0) return;
        Entry e = entries.get(key);
        if (e != null) { e.value = value; touch(e); return; }
        if (entries.size() == capacity) {
            Bucket b = buckets.get(minFrequency);
            Entry victim = b.head.next; b.remove(victim); entries.remove(victim.key);
            if (b.empty()) buckets.remove(minFrequency);
        }
        e = new Entry(key,value); entries.put(key,e);
        buckets.computeIfAbsent(1, ignored -> new Bucket()).add(e);
        minFrequency = 1;
    }
}
```

**Key Logic:**

Every frequency bucket stores an LRU list. Touch removes the entry from its old bucket, deletes an empty bucket and raises minFrequency if necessary, then appends to frequency+1. Insertion resets minimum to one; eviction removes the oldest entry of the minimum bucket. Judge requires LFUCache.

**Time Complexity:** O(1) expected per operation, hash lookup and bucket splices.

**Space Complexity:** O(capacity), live entries and nonempty buckets.

```java
        int val; Entry next;

    }
    private final Entry dummy = new Entry(0);
    private Entry tail = dummy;
    private int size;
    public MyLinkedList() {}

        Entry p = dummy;
        for (int i = 0; i < index; i++) p = p.next;
        return p;
    }
    public int get(int index) {
        return index < 0 || index >= size ? -1 : before(index).next.val;
    }
    public void addAtHead(int val) { addAtIndex(0,val); }
    public void addAtTail(int val) { addAtIndex(size,val); }

        if (index < 0) index = 0;
        if (index > size) return;
        Entry p = index == size ? tail : before(index), e = new Entry(val);
        e.next = p.next; p.next = e;
        if (index == size) tail = e;
        size++;

        Entry p = before(index);
        if (p.next == tail) tail = p;
```

Reverse list, keep running maximum while unlinking dominated nodes, then reverse back; O(n)/O(1). Reverse traversal converts an original right-side condition into a running maximum.

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public ListNode removeNodes(ListNode head) {
        ListNode reversed = reverse(head), prev = null;
        int max = Integer.MIN_VALUE;
        for (ListNode p = reversed; p != null; p = p.next) {
            if (p.val >= max) { max = p.val; prev = p; }
            else prev.next = p.next;
        }
        return reverse(reversed);
    }
    private ListNode reverse(ListNode p) {
        ListNode prev = null;
        while (p != null) {
            ListNode next = p.next; p.next = prev; prev = p; p = next;
        }
        return prev;
    }
}
```

**Key Logic:**

Reverse to expose original suffix values first. Keep the running maximum; bypass nodes strictly smaller than it and retain ties. Reverse the survivors to restore original order.

**Time Complexity:** O(n), two reversals and filtering.

**Space Complexity:** O(1), constant pointers.

## Subpattern L26: Local extrema with index-distance tracking

**When to Apply:** Find spacing between consecutive local minima/maxima in a singly linked list.

**Basic Java Code Snippet:**

```java
int i = 1, first = -1, previous = -1, min = Integer.MAX_VALUE;
for (ListNode a = head, b = head.next; b != null && b.next != null;
     a = b, b = b.next, i++) {
    boolean extreme = (b.val > a.val && b.val > b.next.val)
                   || (b.val < a.val && b.val < b.next.val);
    if (!extreme) continue;
    if (first == -1) first = i;
    else min = Math.min(min, i - previous);
    previous = i;
}
// With at least two extrema, maximum gap is previous - first.
```

**Core Logic:** Only interior nodes can qualify. Consecutive critical positions determine the minimum gap; the first and last determine the maximum gap.

**When to Apply:** Values between marker nodes form independent groups which become output nodes.

```java
class Solution {
    public ListNode mergeNodes(ListNode head) {
        ListNode dummy = new ListNode(), tail = dummy;
        int sum = 0;
        for (ListNode p = head.next; p != null; p = p.next) {
            if (p.val == 0) {

}
```

**Key Logic:**

Skip the initial delimiter, accumulate positive values, emit a node at every subsequent zero, then reset sum. The final zero flushes the last group; no partial group remains.

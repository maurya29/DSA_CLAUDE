## B1 — Exact search and lower/upper bounds

### Subpattern B1: Exact search and lower/upper bounds

**When to Apply:**

Sorted values, a monotone predicate on index, or a first-valid boundary; use half-open [lo,hi).

**Basic Java Code Snippet:**

```java
int lo = 0, hi = a.length;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] < target) lo = mid + 1;
    else hi = mid;
}
// lo is first index with a[index] >= target (or n).
```

**Core Logic:**

This template maintains the B1 search invariant: after each iteration, the candidate interval still contains a valid answer if one exists. The comparison or feasibility test eliminates candidates that cannot satisfy the required boundary. Adapt its predicate and endpoint conventions to the individual problem.

### LeetCode 704

**Question:**

Given an integer array sorted in ascending order and an integer target, return the index of target if it occurs; otherwise return -1. Every index is zero-based. The array contains distinct values. Your algorithm must run in logarithmic time.

**Examples:**

- `nums=[-1,0,3,5,9,12], target=9 → 4`
- `nums=[-1,0,3,5,9,12], target=2 → -1`
- `nums=[5], target=5 → 0.`

**Constraints:**

1 ≤ nums.length ≤ 10⁴; -10⁴ < nums[i], target < 10⁴; distinct sorted nums.

**Why This Subpattern Applies:**

Exact target in sorted array; eliminate half by comparing mid with target. The required search predicate or ordering lets us discard part of the remaining candidates without missing the answer.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int search(int[] nums, int target) {
        int lo = 0, hi = nums.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] == target) return mid;
            if (nums[mid] < target) lo = mid + 1;
            else hi = mid - 1;
        }
        return -1;
    }
}
```

**Key Logic:**

Maintain an inclusive range that could contain target; comparison discards the impossible half. The range shrinks even when the target is absent.

**Time Complexity:**

O(log n).

**Space Complexity:**

O(1).

### LeetCode 34

**Question:**

In a nondecreasing sorted array that may contain duplicates, find the first and last indices of target. Return [-1,-1] if it is absent. Both boundaries must be found in logarithmic time.

**Examples:**

- `nums=[5,7,7,8,8,10], target=8 → [3,4]`
- `target=6 → [-1,-1]`
- `nums=[], target=0 → [-1,-1].`

**Constraints:**

0 ≤ nums.length ≤ 10⁵; -10⁹ ≤ nums[i],target ≤ 10⁹; sorted nondecreasing.

**Why This Subpattern Applies:**

Return first and last index of repeated target. The required search predicate or ordering lets us discard part of the remaining candidates without missing the answer.

**Connection to Previous Solution:**

Extract lowerBound helper and add a second boundary search with <= target instead of < target.

**Java Solution:**

```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int first = bound(nums, target, false);
        if (first == nums.length || nums[first] != target) return new int[]{-1,-1};
        return new int[]{first, bound(nums, target, true) - 1};
    }
    private int bound(int[] a, int target, boolean upper) {
        int lo = 0, hi = a.length;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (a[mid] < target || (upper && a[mid] == target)) lo = mid + 1;
            else hi = mid;
        }
        return lo;
    }
}
```

**Key Logic:**

Lower bound skips values < target; upper bound skips values <= target. Verify first is present before using upper-1, including empty input.

**Time Complexity:**

O(log n).

**Space Complexity:**

O(1) auxiliary; O(1) two-element output.

### LeetCode 744

**Question:**

Given sorted letters (duplicates allowed) and a target letter, return the smallest letter strictly greater than target. The alphabet wraps: if no letter is greater, return the first letter.

**Examples:**

- `letters=["c","f","j"], target="a" → "c"`
- `target="c" → "f"`
- `target="j" → "c".`

**Constraints:**

2 ≤ letters.length ≤ 10⁴; lowercase English letters; sorted nondecreasing; at least two distinct letters.

**Why This Subpattern Applies:**

Find lexicographically smallest sorted letter strictly greater than target with wraparound. The required search predicate or ordering lets us discard part of the remaining candidates without missing the answer.

**Connection to Previous Solution:**

Reuse upperBound from 34, return element at boundary or first element when boundary==n.

**Java Solution:**

```java
class Solution {
    public char nextGreatestLetter(char[] letters, char target) {
        int lo = 0, hi = letters.length;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (letters[mid] <= target) lo = mid + 1;
            else hi = mid;
        }
        return letters[lo % letters.length];
    }
}
```

**Key Logic:**

This is upper bound: equality must move right because the result must be strictly greater. Modulo maps the n boundary to index zero.

**Time Complexity:**

O(log n).

**Space Complexity:**

O(1).

### LeetCode 81

**Question:**

A nondecreasing array with possible duplicates has been rotated. Return whether target occurs anywhere. Duplicates may obscure which half is sorted.

**Examples:**

- `nums=[2,5,6,0,0,1,2], target=0 → true`
- `target=3 → false`
- `nums=[1,0,1,1,1], target=0 → true.`

**Constraints:**

1 ≤ nums.length ≤ 5000; -10⁴ ≤ nums[i],target ≤ 10⁴; duplicates allowed; rotated sorted.

**Why This Subpattern Applies:**

Determine presence when duplicate values obscure which half is sorted. The required search predicate or ordering lets us discard part of the remaining candidates without missing the answer.

**Connection to Previous Solution:**

Insert equality ambiguity branch lo++ and hi-- before normal half selection; worst-case O(n).

**Java Solution:**

```java
class Solution {
    public boolean search(int[] nums, int target) {
        int lo = 0, hi = nums.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] == target) return true;
            if (nums[lo] == nums[mid] && nums[mid] == nums[hi]) {
                lo++; hi--;
            } else if (nums[lo] <= nums[mid]) {
                if (nums[lo] <= target && target < nums[mid]) hi = mid - 1;
                else lo = mid + 1;
            } else {
                if (nums[mid] < target && target <= nums[hi]) lo = mid + 1;
                else hi = mid - 1;
            }
        }
        return false;
    }
}
```

**Key Logic:**

When both ends equal mid, neither half can be certified sorted; trimming both equal endpoints is safe after mid!=target.

**Time Complexity:**

O(log n) typical, O(n) worst.

**Space Complexity:**

O(1).

### LeetCode 540

A sorted array has every value occurring exactly twice in adjacent positions except one value occurring once. Find that single value in logarithmic time using constant extra space.

class Solution {
    public int singleNonDuplicate(int[] nums) {

            if ((mid & 1) == 1) mid--;

class TimeMap {

        final String value;

            this.value = value;
        }
    }

               .add(new Entry(timestamp, value));

        if (entries == null) return "";

            int mid = lo + (hi - lo) / 2;

            else hi = mid;
        }
        return lo == 0 ? "" : entries.get(lo - 1).value;

**Why This Subpattern Applies:**

Median of two individually sorted arrays without merging. The required search predicate or ordering lets us discard part of the remaining candidates without missing the answer.

**Connection to Previous Solution:**

**Java Solution:**

```java
class Solution {
    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        if (nums1.length > nums2.length) return findMedianSortedArrays(nums2, nums1);
        int m = nums1.length, n = nums2.length;
        int leftSize = (m + n + 1) / 2;
        int lo = 0, hi = m;
        while (lo <= hi) {
            int cutA = lo + (hi - lo) / 2;
            int cutB = leftSize - cutA;
            int aLeft = cutA == 0 ? Integer.MIN_VALUE : nums1[cutA - 1];
            int aRight = cutA == m ? Integer.MAX_VALUE : nums1[cutA];
            int bLeft = cutB == 0 ? Integer.MIN_VALUE : nums2[cutB - 1];
            int bRight = cutB == n ? Integer.MAX_VALUE : nums2[cutB];
            if (aLeft <= bRight && bLeft <= aRight) {
                int leftMax = Math.max(aLeft, bLeft);
                if (((m + n) & 1) == 1) return leftMax;
                return ((double) leftMax + Math.min(aRight, bRight)) / 2.0;
            }
            if (aLeft > bRight) hi = cutA - 1;
            else lo = cutA + 1;
        }
        throw new IllegalStateException("Sorted input invariant violated");
    }
}
```

**Key Logic:**

Choose a left partition containing half the total values, rounding up. Cross inequalities guarantee every left value ≤ every right value; shift the cut in the shorter array until valid. Sentinels handle empty sides.

**Time Complexity:**

O(log(min(m,n)+1)).

**Space Complexity:**

O(1) auxiliary; one constant-depth recursive swap.

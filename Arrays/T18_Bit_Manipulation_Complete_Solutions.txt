## Java bitwise conventions

Java `int` has 32 bits and uses signed two’s complement. `>>` sign-extends; `>>>` zero-fills. `&`, `|`, and `^` are bitwise AND, OR, and XOR. `1 << 31` is negative as an `int` but still isolates the sign bit; use `1L << bit` when a positive widened magnitude is required. Java masks shift distances for `int` to five bits and for `long` to six bits; do not shift an int by 32 expecting zero. Parenthesize bitwise expressions before comparison. Complexity notation uses W for word width (32 unless stated), n for input length, and q for query count.

## Subpattern M1: XOR cancellation and odd-occurrence isolation

**When to Apply:**

Use when duplicate occurrences cancel under XOR, leaving exceptional values. XOR folds preserve exactly the bits with odd multiplicity. Equal elements cancel regardless of ordering; a distinguishing set bit separates two exceptions into independently cancellable groups.

**Basic Java Code Snippet:**

```java
int xor = 0;
for (int x : values) xor ^= x;
// Duplicates occurring twice cancel; group by a distinguishing bit if needed.
```

**Core Logic:**

XOR folds preserve exactly the bits with odd multiplicity. Equal elements cancel regardless of ordering; a distinguishing set bit separates two exceptions into independently cancellable groups.

**Questions Covered:** 136, 389, 260

### LeetCode 136

**Question:**

Given a nonempty integer array in which every value occurs twice except one occurring once, return that exceptional value. Use linear time and constant extra space.

**Examples:**

- [2,2,1] → 1
- [4,1,2,1,2] → 4
- [-7] → -7

**Constraints:**

1 ≤ n ≤ 30000; −30000 ≤ nums[i] ≤ 30000; the stated multiplicity guarantee holds.

**Why This Subpattern Applies:**

Pairwise duplicates cancel; XOR all elements to isolate one exceptional value. XOR folds preserve exactly the bits with odd multiplicity.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int singleNumber(int[] nums) {
        int xor = 0;
        for (int x : nums) xor ^= x;
        return xor;
    }
}
```

**Key Logic:**

XOR is associative and commutative; every pair cancels to zero, leaving the singleton even if negative.

**Time Complexity:** O(n), one scan.

**Space Complexity:** O(1), one accumulator.

### LeetCode 389

**Question:**

Given lowercase strings s and t, t is formed by shuffling s and inserting exactly one extra letter at any position. Return the added letter.

**Examples:**

- s="abcd", t="abcde" → e
- s="", t="y" → y
- s="a", t="aa" → a

**Constraints:**

0 ≤ s.length ≤ 1000; t.length = s.length + 1; lowercase English letters.

**Why This Subpattern Applies:**

Exactly one extra character between two character multisets; character order is irrelevant. XOR folds preserve exactly the bits with odd multiplicity.

**Connection to Previous Solution:**

From LC 136: Replace single-array XOR fold with folds over both strings; convert final XOR to char.

**Java Solution:**

```java
class Solution {
    public char findTheDifference(String s, String t) {
        int xor = 0;
        for (int i = 0; i < s.length(); i++) xor ^= s.charAt(i);
        for (int i = 0; i < t.length(); i++) xor ^= t.charAt(i);
        return (char) xor;
    }
}
```

**Key Logic:**

The same character codes cancel across both strings regardless of order; cast the residual integer to char.

**Time Complexity:** O(n), both strings scanned.

**Space Complexity:** O(1), no frequency table.

### LeetCode 260

**Question:**

In an integer array exactly two distinct values appear once; every other value appears twice. Return the two singletons in any order, using linear time and constant auxiliary space.

**Examples:**

- [1,2,1,3,2,5] → [3,5] (either order)
- [-1,0] → [-1,0]
- [0,1] → [0,1]

**Constraints:**

2 ≤ n ≤ 30000; signed 32-bit integers; exactly two singletons.

**Why This Subpattern Applies:**

Exactly two values occur once and all others twice; the combined XOR distinguishes a differing bit. XOR folds preserve exactly the bits with odd multiplicity.

**Connection to Previous Solution:**

From LC 389: Keep XOR cancellation, then add a distinguishing-bit mask and two independent XOR accumulators.

**Java Solution:**

```java
class Solution {
    public int[] singleNumber(int[] nums) {
        int xor = 0;
        for (int x : nums) xor ^= x;
        int bit = xor & -xor, a = 0, b = 0;
        for (int x : nums) {
            if ((x & bit) == 0) a ^= x;
            else b ^= x;
        }
        return new int[]{a, b};
    }
}
```

**Key Logic:**

Total XOR is a^b and nonzero. xor & -xor isolates a differing bit even when it is the sign bit. Duplicates enter the same partition and cancel.

**Time Complexity:** O(n), two scans.

**Space Complexity:** O(1) auxiliary and two output integers.

## Subpattern M2: Prefix XOR reconstruction, range queries and split counting

**When to Apply:**

Use when XOR of a prefix or range determines an encoded value, or matching prefix XORs define valid index splits. Exclusive prefix XOR starts at zero. XOR of two prefix states removes their common prefix; the same identity also inverts adjacent encoded XORs and identifies zero-XOR spans.

**Basic Java Code Snippet:**

```java
int[] px = new int[a.length + 1];
for (int i = 0; i < a.length; i++) px[i + 1] = px[i] ^ a[i];
// XOR of inclusive [l,r] is px[r + 1] ^ px[l].
```

**Core Logic:**

Exclusive prefix XOR starts at zero. XOR of two prefix states removes their common prefix; the same identity also inverts adjacent encoded XORs and identifies zero-XOR spans.

**Questions Covered:** 1720, 2433, 1310, 1442

### LeetCode 1720

**Question:**

An original integer array has length one greater than encoded. Each encoded[i] equals original[i] XOR original[i+1]. Given encoded and the first original value, recover and return the original array.

**Examples:**

- encoded=[1,2,3], first=1 → [1,0,2,1]
- encoded=[6,2,7,3], first=4 → [4,2,0,7,4]

**Constraints:**

2 ≤ original length ≤ 10000; 0 ≤ encoded[i] ≤ 100000; 1 ≤ first ≤ 100000.

**Why This Subpattern Applies:**

Encoded adjacent XORs and first original element are given. Exclusive prefix XOR starts at zero.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int[] decode(int[] encoded, int first) {
        int[] out = new int[encoded.length + 1];
        out[0] = first;
        for (int i = 0; i < encoded.length; i++) out[i+1] = out[i] ^ encoded[i];
        return out;
    }
}
```

**Key Logic:**

XOR both sides with the known preceding original value. Each decoded element makes the next one recoverable.

**Time Complexity:** O(n), one reconstruction pass.

**Space Complexity:** O(1) auxiliary; O(n) output.

### LeetCode 1310

**Question:**

Given an array arr and queries [left,right], return an array containing the XOR of all elements in each inclusive range, in query order.

**Examples:**

- arr=[1,3,4,8], queries=[[0,1],[1,2],[0,3],[3,3]] → [2,7,14,8]
- arr=[4,8,2,10], queries=[[2,3],[1,3],[0,0],[0,3]] → [8,0,4,4]

**Constraints:**

1 ≤ n,q ≤ 30000; 1 ≤ arr[i] ≤ 10^9; 0 ≤ left ≤ right < n.

**Why This Subpattern Applies:**

Many inclusive range XOR queries over a static array. Exclusive prefix XOR starts at zero.

**Connection to Previous Solution:**

From LC 2433: Convert inverse adjacent-prefix relation into arbitrary range-endpoint XOR using a stored prefix array.

**Java Solution:**

```java
class Solution {
    public int[] xorQueries(int[] arr, int[][] queries) {
        int[] p = new int[arr.length + 1];
        for (int i = 0; i < arr.length; i++) p[i+1] = p[i] ^ arr[i];
        int[] ans = new int[queries.length];
        for (int i = 0; i < queries.length; i++) ans[i] = p[queries[i][1]+1] ^ p[queries[i][0]];
        return ans;
    }
}
```

**Key Logic:**

Exclusive prefix P[0]=0 handles ranges starting at zero. XOR of endpoints cancels all elements before left.

**Time Complexity:** O(n+q), preprocessing and constant work per query.

**Space Complexity:** O(n) auxiliary prefix; O(q) output.

### LeetCode 1442

**Question:**

Count triples (i,j,k) satisfying 0 ≤ i < j ≤ k < arr.length for which XOR of arr[i..j−1] equals XOR of arr[j..k]. Both parts must be nonempty.

**Examples:**

- [2,3,1,6,7] → 4
- [1,1,1,1,1] → 10
- [1,2] → 0

**Constraints:**

1 ≤ n ≤ 300; 1 ≤ arr[i] ≤ 10^8.

**Why This Subpattern Applies:**

Count triples where adjacent nonempty subarray XORs are equal. Exclusive prefix XOR starts at zero.

**Connection to Previous Solution:**

From LC 1310: Replace fixed query endpoints with online counts and sums of prior equal prefix states to count all split positions.

**Java Solution:**

```java
class Solution {
    public int countTriplets(int[] arr) {
        java.util.Map<Integer,int[]> seen = new java.util.HashMap<>();
        seen.put(0, new int[]{1,0});
        int p = 0, ans = 0;
        for (int t = 1; t <= arr.length; t++) {
            p ^= arr[t-1];
            int[] state = seen.computeIfAbsent(p, k -> new int[2]);
            ans += state[0] * (t-1) - state[1];
            state[0]++;
            state[1] += t;
        }
        return ans;
    }
}
```

**Key Logic:**

With exclusive prefix endpoint t=k+1, equality means P[i]=P[t]. Each matching earlier i contributes t−i−1 splits. Store count and sum of earlier prefix indices; seed index zero and query before inserting t.

**Time Complexity:** O(n) expected, hash operations.

**Space Complexity:** O(n), distinct prefix states.

## Subpattern M3: Population count and binary-digit DP

**When to Apply:**

Use when the answer depends on how many 1-bits occur, for one integer or every number up to n. Clearing the lowest set bit removes one contribution; shifting right removes the low bit and yields a smaller reusable subproblem. The low bit is extracted with & 1.

**Basic Java Code Snippet:**

```java
int[] bits = new int[n + 1];
for (int i = 1; i <= n; i++) bits[i] = bits[i >> 1] + (i & 1);
```

**Core Logic:**

Clearing the lowest set bit removes one contribution; shifting right removes the low bit and yields a smaller reusable subproblem. The low bit is extracted with & 1.

**Questions Covered:** 191, 338

### LeetCode 191

**Question:**

Return the number of 1 bits in the binary representation of the supplied integer (Hamming weight). The bitwise solution also supports all 32-bit patterns.

**Examples:**

- 11 → 3
- 128 → 1
- 2147483645 → 30

**Constraints:**

Current positive-integer formulation: 1 ≤ n ≤ 2^31−1; older unsigned formulation uses a 32-bit bit pattern.

**Why This Subpattern Applies:**

Count set bits of a 32-bit integer. Clearing the lowest set bit removes one contribution; shifting right removes the low bit and yields a smaller reusable subproblem.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int hammingWeight(int n) {
        int count = 0;
        while (n != 0) {
            n &= n - 1;
            count++;
        }
        return count;
    }
}
```

**Key Logic:**

Subtracting one turns the lowest set bit off and lower zeros on; AND with original clears exactly that bit. Stops at zero, including for negative bit patterns.

**Time Complexity:** O(popcount(n)), at most 32 iterations.

**Space Complexity:** O(1).

## Subpattern M4: Bitwise Hamming differences and position contributions

**When to Apply:**

Use XOR to identify unequal bit positions; aggregate across pairs by counting zeros and ones at each bit. XOR identifies unequal positions. For a collection, count zeros and ones at each position; their cross product counts each unordered mismatching pair exactly once.

**Basic Java Code Snippet:**

```java
int mismatched = Integer.bitCount(x ^ y);
// For all pairs, sum onesAtBit * (n - onesAtBit) at each bit.
```

**Core Logic:**

XOR identifies unequal positions. For a collection, count zeros and ones at each position; their cross product counts each unordered mismatching pair exactly once.

### LeetCode 477

**Question:**

Return the sum of Hamming distances over every unordered pair of distinct indices in nums. Equal values at different indices still form pairs, with distance zero.

**Examples:**

- [4,14,2] → 6
- [4,14,4] → 4
- [0] → 0

**Constraints:**

1 ≤ n ≤ 10000; 0 ≤ nums[i] ≤ 10^9; answer fits signed int.

**Why This Subpattern Applies:**

Sum pairwise bit differences over all unordered integer pairs. XOR identifies unequal positions.

**Connection to Previous Solution:**

From LC 461: Replace single-pair XOR with per-bit combinatorial aggregation across all elements; count cross-bit pairs without enumerating pairs.

**Java Solution:**

```java
class Solution {
    public int totalHammingDistance(int[] nums) {
        long ans = 0;
        for (int bit = 0; bit < 32; bit++) {
            int ones = 0;
            for (int x : nums) ones += (x >>> bit) & 1;
            ans += (long) ones * (nums.length - ones);
        }
        return (int) ans;
    }
}
```

**Key Logic:**

At each bit, every one pairs with every zero, contributing exactly ones*(n−ones) mismatches. Each unordered pair is counted once per differing bit.

**Time Complexity:** O(32n)=O(n), fixed bit scan.

**Space Complexity:** O(1).

## Subpattern M5: Bit-frequency residues for repeated multiplicities

**When to Apply:**

Use when each ordinary value occurs a fixed number of times, so counts modulo that multiplicity reveal an exception. Count set bits independently at every position and reduce modulo the repetition count. Reconstruct the exceptional value, including its sign bit.

**Basic Java Code Snippet:**

```java
int result = 0;
for (int bit = 0; bit < 32; bit++) {
    int count = 0;
    for (int x : a) count += (x >>> bit) & 1;
    if (count % 3 != 0) result |= 1 << bit;
}
```

**Core Logic:**

Count set bits independently at every position and reduce modulo the repetition count. Reconstruct the exceptional value, including its sign bit.

## Subpattern M7: Fixed-width bit reversal

**When to Apply:**

Use when bit positions in a fixed 32-bit representation must be mirrored. Process every bit of the fixed-width word, append the current low bit to a left-shifting result and shift the source logically right. Leading zeros are part of the representation.

**Basic Java Code Snippet:**

```java
int reversed = 0;
for (int i = 0; i < 32; i++) {
    reversed = (reversed << 1) | (n & 1);
    n >>>= 1;
}
```

**Core Logic:**

Process every bit of the fixed-width word, append the current low bit to a left-shifting result and shift the source logically right. Leading zeros are part of the representation.

Reverse the order of all 32 bits of an integer, including leading zero positions. Return the resulting 32-bit pattern; Java int may represent it as a negative number.

## Subpattern M8: Common-prefix range AND

**When to Apply:**

Use when bitwise AND of every integer in a consecutive numeric interval is required. All consecutive values share a common high-bit prefix until the first differing position. Every bit below that boundary becomes zero under AND across the range.

**Basic Java Code Snippet:**

```java
int shifts = 0;
while (left != right) {
    left >>>= 1; right >>>= 1; shifts++;
}
int common = left << shifts;
```

**Core Logic:**

All consecutive values share a common high-bit prefix until the first differing position. Every bit below that boundary becomes zero under AND across the range.

```java
class Bitset {
    private final boolean[] raw;
    private boolean flipped;
    private int ones;
    public Bitset(int size) { raw = new boolean[size]; }
    public void fix(int idx) {
        if (!(raw[idx] ^ flipped)) {
            raw[idx] = !flipped;
            ones++;
        }
    }
    public void unfix(int idx) {
        if (raw[idx] ^ flipped) {
            raw[idx] = flipped;
            ones--;
        }
    }
    public void flip() { flipped = !flipped; ones = raw.length-ones; }
    public boolean all() { return ones == raw.length; }
    public boolean one() { return ones > 0; }
    public int count() { return ones; }
    public String toString() {
        StringBuilder out = new StringBuilder(raw.length);
        for (boolean bit : raw) out.append((bit ^ flipped) ? '1' : '0');
        return out.toString();
    }
}
```

```java
        if (dividend == Integer.MIN_VALUE && divisor == -1) return Integer.MAX_VALUE;
        long a = Math.abs((long) dividend), b = Math.abs((long) divisor);
        long q = 0;
        for (int shift = 31; shift >= 0; shift--) {
            if ((a >>> shift) >= b) {
                a -= b << shift;
                q |= 1L << shift;
            }
        }
        return (int) (((dividend < 0) ^ (divisor < 0)) ? -q : q);
    }
}
```

**Key Logic:**

Widen before taking absolute value to represent 2^31. At each descending bit, subtract divisor shifted by that bit if it fits, recording the quotient bit. Apply sign after magnitude calculation and clamp the sole positive overflow case.

**Time Complexity:** O(32)=O(1), fixed descending bit scan.

**Space Complexity:** O(1).

Minimize bit flips so OR of two numbers equals a third. Each position is independent.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int minFlips(int a, int b, int c) {
        int ans = 0;
        for (int i = 0; i < 32; i++) {
            int x = (a >>> i)&1, y = (b >>> i)&1, z = (c >>> i)&1;
            if (z == 0) ans += x+y;
            else if ((x | y) == 0) ans++;
        }
        return ans;
    }
}
```

**Key Logic:**

If desired bit is zero, every set operand bit must be cleared independently. If desired is one, only the case of two zero operands needs a flip. Sum independent minimum costs.

## Subpattern M20: Subset-XOR contribution identity

**When to Apply:**

Use when asked for sum of XOR over all index-selected subsets, not to enumerate each subset. For each present bit, toggling inclusion of one element with that bit pairs subsets of opposite XOR parity. Exactly half contribute the bit, and the OR of all values identifies the contributing positions.

```java
    if (values.length == 0) return 0;

    return (long) allBits << (values.length - 1);
} // for nonnegative values and a result that fits long
```

**Core Logic:**

## I1 — Sort-and-merge overlapping intervals

### When to Apply

Unsorted closed intervals must be merged or counted as overlap-connected components. Sort by start; the current component ends at the largest right endpoint encountered.

### Basic Java Code Snippet

```java
java.util.Arrays.sort(ranges, java.util.Comparator.comparingInt(a -> a[0]));
int start = ranges[0][0], end = ranges[0][1];
for (int i = 1; i < ranges.length; i++) {
    if (ranges[i][0] <= end) end = Math.max(end, ranges[i][1]);
    else {
        // emit/count finished component [start,end]
        start = ranges[i][0]; end = ranges[i][1];
    }
}
// emit/count final component; guard empty input.
```

### Core Logic

Unsorted closed intervals must be merged or counted as overlap-connected components. Sort by start; the current component ends at the largest right endpoint encountered.

### LeetCode 56

**Question:**

Given an array of closed intervals [start,end], combine every pair or chain of intervals sharing any point. Return the resulting disjoint intervals covering exactly the original union; output may be in any order. Touching endpoints count as overlapping.

**Examples:**

- `[[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]]`
- `[[1,4],[4,5]] → [[1,5]]`
- `[[1,4],[2,3]] → [[1,4]].`

**Constraints:**

1 ≤ intervals.length ≤ 10^4; 0 ≤ start ≤ end ≤ 10^4.

**Why This Subpattern Applies:**

Sorting by left endpoint makes every interval overlapping the current merged component consecutive.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int[][] merge(int[][] intervals) {
        java.util.Arrays.sort(intervals, java.util.Comparator.comparingInt(a -> a[0]));
        java.util.List<int[]> result = new java.util.ArrayList<>();
        int start = intervals[0][0], end = intervals[0][1];
        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] <= end) end = Math.max(end, intervals[i][1]);
            else { result.add(new int[]{start, end}); start = intervals[i][0]; end = intervals[i][1]; }
        }
        result.add(new int[]{start, end});
        return result.toArray(new int[result.size()][]);
    }
}
```

**Key Logic:**

Sort starts; retain the current merged range. Extend its end on overlap, otherwise append it and start a new component.

**Time Complexity:**

O(n log n) time for sorting

**Space Complexity:**

O(n) output and O(log n) sorting stack (implementation-dependent).

### LeetCode 57

**Question:**

Given nonoverlapping closed intervals already sorted by start and one additional closed interval, insert it and merge any overlaps. Return a sorted disjoint list; do not lose existing intervals.

**Examples:**

- `[[1,3],[6,9]], [2,5] → [[1,5],[6,9]]`
- `[[1,2],[3,5],[6,7],[8,10],[12,16]], [4,8] → [[1,2],[3,10],[12,16]]`
- `[], [5,7] → [[5,7]].`

**Constraints:**

0 ≤ intervals.length ≤ 10^4; 0 ≤ start ≤ end ≤ 10^5; original intervals sorted and pairwise disjoint.

**Why This Subpattern Applies:**

Existing order removes the need to sort: only a contiguous middle block can overlap the inserted interval.

**Connection to Previous Solution:**

merge test and endpoint min/max; replace global sorting with three linear phases around the inserted range.

**Java Solution:**

```java
class Solution {
    public int[][] insert(int[][] intervals, int[] newInterval) {
        java.util.List<int[]> out = new java.util.ArrayList<>();
        int i = 0, n = intervals.length;
        while (i < n && intervals[i][1] < newInterval[0]) out.add(intervals[i++]);
        int start = newInterval[0], end = newInterval[1];
        while (i < n && intervals[i][0] <= end) {
            start = Math.min(start, intervals[i][0]);
            end = Math.max(end, intervals[i][1]);
            i++;
        }
        out.add(new int[]{start, end});
        while (i < n) out.add(intervals[i++]);
        return out.toArray(new int[out.size()][]);
    }
}
```

**Key Logic:**

First copy ranges ending before the new start; merge while next start ≤ new end; append remaining ranges. Endpoints are inclusive.

**Time Complexity:**

O(n) time, O(n) output space

**Space Complexity:**

O(1) extra beyond output.

### LeetCode 2580

**Question:**

Given closed integer ranges, assign each entire range to one of two labeled groups. If two ranges overlap, they must be placed in the same group. Count all valid assignments modulo 1,000,000,007; either group may be empty.

**Examples:**

- `[[6,10],[5,15]] → 2`
- `[[1,3],[10,20],[2,5],[4,8]] → 4`
- `[[1,1],[3,3]] → 4.`

**Constraints:**

1 ≤ ranges.length ≤ 10^5; 0 ≤ left ≤ right ≤ 10^9.

**Why This Subpattern Applies:**

Overlapping ranges form connected components, and each component independently chooses one of two groups.

**Connection to Previous Solution:**

sorted merge-component detection; replace emitting intervals with incrementing component count and exponentiating 2.

**Java Solution:**

```java
class Solution {
    public int countWays(int[][] ranges) {
        java.util.Arrays.sort(ranges, java.util.Comparator.comparingInt(a -> a[0]));
        long ways = 1;
        int end = -1;
        for (int[] r : ranges) {
            if (r[0] > end) ways = ways * 2 % 1_000_000_007;
            end = Math.max(end, r[1]);
        }
        return (int) ways;
    }
}
```

**Key Logic:**

Sort starts, count a new component only when start > previous merged end. Multiply the answer by two for each component modulo 1e9+7.

**Time Complexity:**

O(n log n) time

**Space Complexity:**

O(log n) sorting stack, O(1) other auxiliary space.

### LeetCode 986

**Question:**

Two lists of closed intervals are each sorted by start and internally pairwise disjoint. Return every nonempty intersection between one interval from the first list and one from the second, sorted by start. Shared endpoints form singleton intersections.

**Examples:**

- `[[0,2],[5,10],[13,23],[24,25]], [[1,5],[8,12],[15,24],[25,26]] → [[1,2],[5,5],[8,10],[15,23],[24,24],[25,25]]`
- `[[1,3]], [] → []`
- `[[1,2]], [[2,3]] → [[2,2]].`

**Constraints:**

0 ≤ list lengths ≤ 1000; 0 ≤ start ≤ end ≤ 10^9; each list sorted, internally disjoint.

**Why This Subpattern Applies:**

Only the two current intervals can create the next intersection; the earlier-ending one cannot overlap any later interval of the opposite stream.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int[][] intervalIntersection(int[][] firstList, int[][] secondList) {
        java.util.List<int[]> out = new java.util.ArrayList<>();
        int i = 0, j = 0;
        while (i < firstList.length && j < secondList.length) {
            int left = Math.max(firstList[i][0], secondList[j][0]);
            int right = Math.min(firstList[i][1], secondList[j][1]);
            if (left <= right) out.add(new int[]{left, right});
            if (firstList[i][1] < secondList[j][1]) i++; else j++;
        }
        return out.toArray(new int[out.size()][]);
    }
}
```

**Key Logic:**

Intersection is [max(starts), min(ends)] if start ≤ end. Advance whichever interval ends first (either on a tie).

**Time Complexity:**

O(n+m) time

**Space Complexity:**

O(k) output space, O(1) auxiliary excluding output.

### LeetCode 1229

**Question:**

Two people provide available time slots [start,end], and a positive meeting duration. Find the earliest starting interval [t,t+duration] that fits entirely within one slot from each person. Return [] when no such meeting exists. Slots for each person do not overlap but are not necessarily sorted.

**Examples:**

- `[[10,50],[60,120],[140,210]], [[0,15],[60,70]], 8 → [60,68]`
- `[[10,50]], [[0,15]], 10 → []`
- `[[1,10]], [[3,8]], 5 → [3,8].`

**Constraints:**

1 ≤ slot-list lengths ≤ 10^4; 0 ≤ start < end ≤ 10^9; 1 ≤ duration ≤ 10^6; each person’s slots do not overlap.

**Why This Subpattern Applies:**

After sorting both streams, their current overlap is the earliest possible candidate not yet eliminated.

**Connection to Previous Solution:**

Retain intersection and earlier-end advance; change output to early return when overlap length >= duration, otherwise continue.

**Java Solution:**

```java
class Solution {
    public java.util.List<Integer> minAvailableDuration(int[][] slots1, int[][] slots2, int duration) {
        java.util.Arrays.sort(slots1, java.util.Comparator.comparingInt(a -> a[0]));
        java.util.Arrays.sort(slots2, java.util.Comparator.comparingInt(a -> a[0]));
        int i = 0, j = 0;
        while (i < slots1.length && j < slots2.length) {
            int start = Math.max(slots1[i][0], slots2[j][0]);
            int end = Math.min(slots1[i][1], slots2[j][1]);
            if ((long) end - start >= duration) return java.util.List.of(start, start + duration);
            if (slots1[i][1] < slots2[j][1]) i++; else j++;
        }
        return java.util.List.of();
    }
}
```

**Key Logic:**

Sort each list, compute max start and min end; return [start,start+duration] when end-start ≥ duration; otherwise advance earlier-ending slot.

**Time Complexity:**

**Space Complexity:**

O(log n + log m) sorting stack, O(1) other auxiliary space.

## I3 — Earliest-finish compatible scheduling

### When to Apply

Maximize compatible interval selections or minimize removals. Choosing the earliest finishing compatible interval leaves maximal room for future choices.

### Basic Java Code Snippet

```java
for (int[] in : a) {
    if (in[0] >= lastEnd) { // change to > for strict chains
        kept++; lastEnd = in[1];

}
```

Given time intervals, remove the minimum number so that no two remaining intervals overlap. Intervals meeting exactly at an endpoint are compatible. Return the number removed, not the remaining intervals.

**Connection to Previous Solution:**

```java
class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        java.util.Arrays.sort(intervals, java.util.Comparator.comparingInt(a -> a[1]));
        int kept = 0;
        long lastEnd = Long.MIN_VALUE;
        for (int[] in : intervals) {
            if (in[0] >= lastEnd) { kept++; lastEnd = in[1]; }
```

## I4 — Minimum points piercing closed intervals

## I5 — Greedy full-range coverage

### When to Apply

Cover an entire continuous target using as few intervals as possible. At each reachable frontier, extend to the farthest end of any eligible interval.

### Basic Java Code Snippet

```java
// Sort segments by start first (or preprocess farthestRight[start]).
int i = 0, covered = 0, chosen = 0;
while (covered < target) {
    int farthest = covered;
    while (i < segments.length && segments[i][0] <= covered)
        farthest = Math.max(farthest, segments[i++][1]);
    if (farthest == covered) { /* impossible to cover target */ break; }
    covered = farthest;
    chosen++;
}
```

### Core Logic

Cover an entire continuous target using as few intervals as possible. At each reachable frontier, extend to the farthest end of any eligible interval.

### LeetCode 1024

**Question:**

Each video clip [start,end] covers a continuous part of a video. You may trim clips freely. Return the minimum number of clips whose union covers every instant from 0 through time, or -1 if impossible.

**Examples:**

- `[[0,2],[4,6],[8,10],[1,9],[1,5],[5,9]], 10 → 3`
- `[[0,1],[1,2]], 5 → -1`
- `[[0,4],[2,8]], 8 → 2.`

**Constraints:**

1 ≤ clips.length ≤ 100; 0 ≤ start ≤ end ≤ 100; 0 ≤ time ≤ 100.

**Why This Subpattern Applies:**

At each covered frontier, all clips starting at or before it are candidates; taking the farthest-reaching one cannot increase the minimum count.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int videoStitching(int[][] clips, int time) {
        java.util.Arrays.sort(clips, java.util.Comparator.comparingInt(a -> a[0]));
        int i = 0, covered = 0, used = 0;
        while (covered < time) {
            int farthest = covered;
            while (i < clips.length && clips[i][0] <= covered)
                farthest = Math.max(farthest, clips[i++][1]);
            if (farthest == covered) return -1;
            covered = farthest;
            used++;
        }
        return used;
    }
}
```

**Key Logic:**

Sort by start; scan all reachable clips, commit the farthest endpoint, and fail if frontier does not advance. A zero-length target needs zero clips.

**Time Complexity:**

O(n log n) time

**Space Complexity:**

O(log n) sorting stack, O(1) other auxiliary space.

### LeetCode 1326

**Question:**

A garden spans [0,n]. Tap i at integer position i waters [i−ranges[i], i+ranges[i]], clipped to garden boundaries. Choose the fewest taps whose watered regions cover the entire garden; return -1 if impossible.

**Examples:**

- `n=5, ranges=[3,4,1,1,0,0] → 1`
- `n=3, ranges=[0,0,0,0] → -1`
- `n=7, ranges=[1,2,1,0,2,1,0,1] → 3.`

**Constraints:**

1 ≤ n ≤ 10^4; ranges.length = n+1; 0 ≤ ranges[i] ≤ 100.

**Why This Subpattern Applies:**

Each tap is an interval, so minimum continuous coverage uses the same farthest-frontier greedy invariant.

**Connection to Previous Solution:**

Keep greedy coverage frontier; replace input clips with position-derived intervals (optionally preprocess farthestRight[left] for linear scan).

**Java Solution:**

```java
class Solution {
    public int minTaps(int n, int[] ranges) {
        int[] reach = new int[n + 1];
        for (int i = 0; i <= n; i++) {
            int left = Math.max(0, i - ranges[i]);
            int right = Math.min(n, i + ranges[i]);
            reach[left] = Math.max(reach[left], right);
        }
        int farthest = 0, covered = 0, used = 0;
        for (int i = 0; i < n; i++) {
            farthest = Math.max(farthest, reach[i]);
            if (i == covered) {
                if (farthest <= i) return -1;
                used++;
                covered = farthest;
            }
        }
        return used;
    }
}
```

**Key Logic:**

Convert each tap into a farthest reachable right endpoint indexed by left boundary; sweep positions, updating farthest reach and committing a tap when the current coverage ends.

**Time Complexity:**

O(n) time and O(n) auxiliary space for farthest reach.

**Space Complexity:**

See complexity statement above.

## I6 — Event-coordinate sweeping and aggregation

### When to Apply

A count or weighted sum changes only at endpoints. Accumulate ordered event deltas; distinguish closed end+1 from half-open end.

### Basic Java Code Snippet

```java
    long start = in[0], endExclusive = (long) in[1] + 1;
    delta.merge(start, 1L, Long::sum);

for (var entry : delta.entrySet()) {

```

### LeetCode 1854

**Question:**

Each person has a birth year and death year. They count as alive in every year from birth through death−1, not in their death year. Return the earliest year having the maximum living population.

**Examples:**

- `[[1993,1999],[2000,2010]] → 1993`
- `[[1950,1961],[1960,1971],[1970,1981]] → 1960`
- `[[1950,1951]] → 1950.`

**Constraints:**

1 ≤ logs.length ≤ 100; 1950 ≤ birth < death ≤ 2050.

**Why This Subpattern Applies:**

The living population changes only at births and deaths, so endpoint deltas recover the count in chronological order.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int maximumPopulation(int[][] logs) {
        int[] delta = new int[102];
        for (int[] log : logs) { delta[log[0] - 1950]++; delta[log[1] - 1950]--; }
        int active = 0, best = 0, answer = 1950;
        for (int y = 0; y <= 100; y++) {
            active += delta[y];
            if (active > best) { best = active; answer = y + 1950; }
        }
        return answer;
    }
}
```

**Key Logic:**

Add +1 at birth and −1 at death. Sweep ascending years; update the best year only for a strictly greater count, preserving earliest ties.

### LeetCode 2406

**Question:**

Given closed integer intervals, partition them into the fewest groups such that no two intervals in the same group share a point. Return the minimum group count. Touching endpoints conflict.

**Examples:**

- `[[5,10],[6,8],[1,5],[2,3],[1,10]] → 3`
- `[[1,3],[5,6],[8,10],[11,13]] → 1`
- `[[1,2],[2,3]] → 2.`

**Constraints:**

1 ≤ intervals.length ≤ 10^5; 1 ≤ left ≤ right ≤ 10^6.

**Why This Subpattern Applies:**

The minimum number of groups equals the maximum number of intervals active at one coordinate.

**Connection to Previous Solution:**

chronological event delta/prefix peak; change half-open death cancellation to closed end+1 cancellation.

**Java Solution:**

```java
class Solution {
    public int minGroups(int[][] intervals) {
        java.util.TreeMap<Long, Integer> delta = new java.util.TreeMap<>();
        for (int[] in : intervals) {
            delta.merge((long) in[0], 1, Integer::sum);
            delta.merge((long) in[1] + 1, -1, Integer::sum);
        }
        int active = 0, best = 0;
        for (int change : delta.values()) { active += change; best = Math.max(best, active); }
        return best;
    }
}
```

**Key Logic:**

Convert closed [l,r] to events +1 at l and −1 at r+1; sweep event coordinates to find peak overlap.

**Time Complexity:**

O(n log n) time for ordered events

**Space Complexity:**

O(n) auxiliary space.

```java
    public java.util.List<java.util.List<Long>> splitPainting(int[][] segments) {
        java.util.TreeMap<Integer, Long> delta = new java.util.TreeMap<>();
        for (int[] s : segments) {
            delta.merge(s[0], (long) s[2], Long::sum);
```

```java
class SummaryRanges {

    public SummaryRanges() {}
    public void addNum(int value) {
        var left = ranges.floorEntry(value);
        if (left != null && left.getValue() >= value) return;
        int start = value, end = value;
        if (left != null && (long) left.getValue() + 1 >= value) {
            start = left.getKey();
            ranges.remove(left.getKey());
        }
        var right = ranges.ceilingEntry(value);
        if (right != null && (long) right.getKey() <= (long) end + 1) {
            end = Math.max(end, right.getValue());
            ranges.remove(right.getKey());

        ranges.put(start, end);
```

```java
class CountIntervals {
    private final java.util.TreeMap<Integer, Integer> ranges = new java.util.TreeMap<>();
    private long covered = 0;
    public CountIntervals() {}
    public void add(int left, int right) {
        var e = ranges.floorEntry(left);
        if (e == null || e.getValue() < left) e = ranges.ceilingEntry(left);
        while (e != null && e.getKey() <= right) {
            left = Math.min(left, e.getKey());
            right = Math.max(right, e.getValue());
            covered -= (long) e.getValue() - e.getKey() + 1;
            ranges.remove(e.getKey());
            e = ranges.ceilingEntry(left);
        }
        ranges.put(left, right);
        covered += (long) right - left + 1;
    }
    public int count() { return (int) covered; }
}
```

**Key Logic:**

Find floor interval intersecting the new range; repeatedly absorb every interval starting no later than current right, subtract its old length, and insert merged range.

**Question:**

Design RangeModule over real-number coordinates, represented by half-open intervals. addRange(left,right) tracks every point in [left,right); queryRange(left,right) returns whether every point is currently tracked; removeRange(left,right) untracks those points. **Why This Subpattern Applies:**

A TreeMap of disjoint half-open covered ranges supports predecessor containment, union on addition, and splitting on removal.

**Connection to Previous Solution:**

**Java Solution:**

```java
class RangeModule {
    private final java.util.TreeMap<Integer, Integer> ranges = new java.util.TreeMap<>();
    public RangeModule() {}
    public void addRange(int left, int right) {
        var e = ranges.floorEntry(left);
        if (e == null || e.getValue() < left) e = ranges.ceilingEntry(left);
        while (e != null && e.getKey() <= right) {
            left = Math.min(left, e.getKey());
            right = Math.max(right, e.getValue());
            ranges.remove(e.getKey());
            e = ranges.ceilingEntry(left);
        }
        ranges.put(left, right);
    }
    public boolean queryRange(int left, int right) {
        var e = ranges.floorEntry(left);
        return e != null && e.getValue() >= right;
    }
    public void removeRange(int left, int right) {
        var e = ranges.floorEntry(left);
        if (e == null || e.getValue() <= left) e = ranges.ceilingEntry(left);
        while (e != null && e.getKey() < right) {
            int start = e.getKey(), end = e.getValue();
            ranges.remove(start);
            if (start < left) ranges.put(start, left);
            if (end > right) { ranges.put(right, end); break; }
            e = ranges.ceilingEntry(left);
        }
    }
}
```

**Key Logic:**

Add: merge every overlapping range, including predecessor. Query: predecessor end ≥ right. Remove: delete overlaps and reinsert surviving left/right fragments.

**Time Complexity:**

add/remove O((k+1) log n) for k affected ranges

**Space Complexity:**

query O(log n); O(n) stored intervals.

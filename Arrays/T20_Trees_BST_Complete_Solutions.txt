## T1 — Bottom-up height and subtree metrics

**NEW ALGORITHM FAMILY**

**Recognition:** A node result depends on recursively computed child heights; O(n) postorder visits.

**Core reusable logic:** return 1+max(child heights), with null height 0.

**Ordered questions:** LC 104, LC 111, LC 110, LC 543

**Reusable Java 21 template (invariant sketch from master curriculum; not a standalone submission):**

```java
int height(TreeNode node) {
    if (node == null) return 0;
    int l = height(node.left), r = height(node.right);
    // combine child heights; optionally update a global best/flag
    return 1 + Math.max(l, r);
}
```

### LC 104 — Question 01/58

**Problem statement**

Return the number of nodes on the longest path from the root to a leaf. An empty tree has depth zero.

**Examples**

1. root=[3,9,20,null,null,15,7] → 3
2. root=[] → 0

**Constraints**

0–10,000 nodes; values −100 to 100.

**Why this belongs to the family**

A node result depends on recursively computed child heights; O(n) postorder visits.

**Exact implementation evolution**

Foundation of this subpattern. return 1+max(child heights), with null height 0.

**Complete Java solution**

```java
import java.util.*;

class Solution {
    public int maxDepth(TreeNode root) {
        if (root == null) return 0;
        return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
    }
}
```

**Key logic / correctness invariant**

Null contributes zero. Each parent adds one to the greater child height.

**Complexity**

- Time: O(n).
- Space: O(h).

### LC 111 — Question 02/58

**Problem statement**

Return the number of nodes on the shortest root-to-leaf path. A leaf has no children; a missing child is not a leaf.

**Examples**

1. root=[3,9,20,null,null,15,7] → 2
2. root=[1,null,2,null,3] → 3

**Constraints**

0–100,000 nodes; values −1000 to 1000.

**Why this belongs to the family**

A node result depends on recursively computed child heights; O(n) postorder visits.

**Exact implementation evolution**

Replace max with leaf-aware minimum; explicitly distinguish leaf from missing child.

**Complete Java solution**

```java
import java.util.*;

class Solution {
    public int minDepth(TreeNode root) {
        if (root == null) return 0;
        int l = minDepth(root.left), r = minDepth(root.right);
        return 1 + (l == 0 || r == 0 ? l + r : Math.min(l, r));
    }
}
```

**Key logic / correctness invariant**

When only one child exists, use its depth. When both exist, take the minimum.

**Complexity**

- Time: O(n).
- Space: O(h).

### LC 110 — Question 03/58

**Problem statement**

Determine whether every node has left and right subtree heights differing by at most one.

**Examples**

1. root=[3,9,20,null,null,15,7] → true
2. root=[1,2,null,3] → false

**Constraints**

0–5000 nodes; values −10,000 to 10,000.

**Why this belongs to the family**

A node result depends on recursively computed child heights; O(n) postorder visits.

**Exact implementation evolution**

Replace positive minimum depth with height plus abs(left-right)<=1 and propagate invalid sentinel.

**Complete Java solution**

```java
import java.util.*;

class Solution {
    public boolean isBalanced(TreeNode root) { return height(root) != -1; }
    private int height(TreeNode n) {
        if (n == null) return 0;
        int l = height(n.left);
        if (l == -1) return -1;
        int r = height(n.right);
        if (r == -1 || Math.abs(l-r) > 1) return -1;
        return 1 + Math.max(l,r);
    }
}
```

**Key logic / correctness invariant**

Propagate −1 immediately when a descendant is unbalanced or child heights differ by more than one.

**Complexity**

- Time: O(n).
- Space: O(h).

### LC 543 — Question 04/58

**Problem statement**

Return the maximum number of edges on a path connecting any two nodes. The path need not pass through the root.

**Examples**

1. root=[1,2,3,4,5] → 3
2. root=[1] → 0

**Constraints**

1–10,000 nodes; values −100 to 100.

**Why this belongs to the family**

A node result depends on recursively computed child heights; O(n) postorder visits.

**Exact implementation evolution**

Reuse postorder heights; replace balance sentinel with global maximum l+r while still returning height.

**Complete Java solution**

```java
import java.util.*;

class Solution {
    private int best;
    public int diameterOfBinaryTree(TreeNode root) { best=0; height(root); return best; }
    private int height(TreeNode n) {
        if (n==null) return 0;
        int l=height(n.left), r=height(n.right);
        best=Math.max(best,l+r);
        return 1+Math.max(l,r);
    }
}
```

**Key logic / correctness invariant**

At each node, left height plus right height gives the longest path passing through it. Return height to parent and update global best.

**Complexity**

- Time: O(n).
- Space: O(h).

### LC 114 — Question 08/58

**Problem statement**

Modify the tree into a right-linked chain of the same nodes in preorder traversal order; every left pointer must be null.

**Examples**

1. root=[1,2,5,3,4,null,6] → [1,null,2,null,3,null,4,null,5,null,6]
2. root=[0] → [0]

**Constraints**

0–2000 nodes; values −100 to 100. Must mutate in place.

**Why this belongs to the family**

Modify child pointers without creating a replacement tree.

**Exact implementation evolution**

Replace local child swap with reverse-preorder previous-node linkage (right then left DFS); maintain one evolving chain.

**Complete Java solution**

```java
import java.util.*;

class Solution {
    private TreeNode prev;
    public void flatten(TreeNode root) { prev=null; dfs(root); }
    private void dfs(TreeNode n) {
        if(n==null) return;
        dfs(n.right); dfs(n.left);
        n.right=prev; n.left=null; prev=n;
    }
}
```

**Key logic / correctness invariant**

Process right then left then node. Link current node to the already flattened suffix stored in prev.

**Complexity**

- Time: O(n).
- Space: O(h).

class Solution {

### LC 2415 — Question 14/58

**Problem statement**

Given a perfect binary tree, reverse the values (not pointers) at every odd depth, with root at depth zero. Return root.

**Examples**

1. root=[2,3,5,8,13,21,34] → [2,5,3,8,13,21,34]
2. root=[7] → [7]

**Constraints**

**Why this belongs to the family**

**Complete Java solution**

```java
import java.util.*;

class Solution {
    public TreeNode reverseOddLevels(TreeNode root) {
        if(root==null) return null;
        Deque<TreeNode> q=new ArrayDeque<>(); q.add(root); int depth=0;
        while(!q.isEmpty()) {
            int size=q.size(); List<TreeNode> level=new ArrayList<>();
            for(int i=0;i<size;i++) {
                TreeNode n=q.remove();
                if((depth&1)==1) level.add(n);
                if(n.left!=null) q.add(n.left);
                if(n.right!=null) q.add(n.right);
            }
            for(int l=0,r=level.size()-1;l<r;l++,r--) {
                int temp=level.get(l).val; level.get(l).val=level.get(r).val; level.get(r).val=temp;
            }
            depth++;
        }
        return root;
    }
}
```

**Key logic / correctness invariant**

Collect references for the odd layer and swap values from both ends; even layers are unchanged.

**Complexity**

- Time: O(n).

## T5 — Next-right link construction

**NEW ALGORITHM FAMILY**

**Recognition:** Populate next pointers among peers, and avoid linking across level boundaries.

**Core reusable logic:** connect sibling and cross-parent children using next, then descend to next level.

**Ordered questions:** LC 116, LC 117

**Reusable Java 21 template (invariant sketch from master curriculum; not a standalone submission):**

```java
Node level = root;
while (level != null) {
    Node dummy = new Node(0), tail = dummy;
    for (Node cur = level; cur != null; cur = cur.next) {
        if (cur.left != null) { tail.next = cur.left; tail = tail.next; }
        if (cur.right != null) { tail.next = cur.right; tail = tail.next; }
    }
    level = dummy.next;

    dirs.setLength(dirs.length()-1);
    dirs.append('R');
    if (path(n.right, target, dirs)) return true;
    dirs.setLength(dirs.length()-1);
    return false;
}
```

### LC 2096 — Question 56/58

**Problem statement**

Given two distinct node values startValue and destValue, return directions along the shortest tree path from start to destination. Use U for parent, L for left child, and R for right child.

**Examples**

1. root=[5,1,2,3,null,6,4], startValue=3, destValue=6 → "UURL"
2. root=[2,1], startValue=2, destValue=1 → "L"

**Constraints**

2–100,000 nodes; values unique in 1–n; both values exist and differ.

**Why this belongs to the family**

Find root-to-node directions, discard common prefix and encode upward moves.

**Exact implementation evolution**

Foundation of this subpattern. derive each root path, remove shared prefix, combine U repetitions and destination suffix.

**Complete Java solution**

```java
import java.util.*;

class Solution {
    private record Link(TreeNode parent,char dir) {}
    public String getDirections(TreeNode root,int startValue,int destValue) {
        Map<TreeNode,Link> parent=new HashMap<>(); Deque<TreeNode> q=new ArrayDeque<>(); q.add(root);
        TreeNode start=null,dest=null;
        while(!q.isEmpty()) {
            TreeNode n=q.remove(); if(n.val==startValue) start=n; if(n.val==destValue) dest=n;
            if(n.left!=null) {parent.put(n.left,new Link(n,'L')); q.add(n.left);}
            if(n.right!=null) {parent.put(n.right,new Link(n,'R')); q.add(n.right);}
        }
        String a=path(start,parent),b=path(dest,parent); int i=0;
        while(i<a.length() && i<b.length() && a.charAt(i)==b.charAt(i)) i++;
        return "U".repeat(a.length()-i)+b.substring(i);
    }
    private String path(TreeNode n,Map<TreeNode,Link> parent) {
        StringBuilder out=new StringBuilder();
        while(parent.containsKey(n)) {Link link=parent.get(n); out.append(link.dir()); n=link.parent();}
        return out.reverse().toString();
    }
}
```

**Key logic / correctness invariant**

Find root-to-start and root-to-destination direction strings, skip their shared prefix, replace remaining start steps with U, and append destination suffix. Iterative parent-map path construction avoids deep recursion.

**Complexity**

- Time: O(n).
- Space: O(n).

### LC 2458 — Question 57/58

**Problem statement**

For each independent query giving a non-root node value, hypothetically remove that entire subtree and report the remaining tree height in edges. Queries do not permanently modify the original tree.

**Examples**

1. root=[1,3,4,2,null,6,5,null,null,null,null,null,7], queries=[4] → [2]
2. root=[1,2,3], queries=[2,3] → [1,1]

**Constraints**

2–100,000 nodes; unique values 1–n; 1–10,000 queries; query never equals root.

**Why this belongs to the family**

Many subtree-removal height queries require reusable DFS entry/exit intervals and prefix/suffix maxima.

**Exact implementation evolution**

Foundation of this subpattern. subtree is contiguous DFS interval; preprocessing prefix/suffix max depths allows O(1) exclusion query.

**Complete Java solution**

```java
import java.util.*;

class Solution {
    private record Frame(TreeNode node,int depth,boolean exit) {}
    public int[] treeQueries(TreeNode root,int[] queries) {
        Map<Integer,Integer> tin=new HashMap<>(),tout=new HashMap<>(); List<Integer> depth=new ArrayList<>();
        Deque<Frame> stack=new ArrayDeque<>(); stack.push(new Frame(root,0,false));
        while(!stack.isEmpty()) {
            Frame f=stack.pop(); TreeNode n=f.node();
            if(f.exit()) {tout.put(n.val,depth.size()); continue;}
            tin.put(n.val,depth.size()); depth.add(f.depth());
            stack.push(new Frame(n,f.depth(),true));
            if(n.right!=null) stack.push(new Frame(n.right,f.depth()+1,false));
            if(n.left!=null) stack.push(new Frame(n.left,f.depth()+1,false));
        }
        int n=depth.size(); int[] pre=new int[n+1],suf=new int[n+1]; pre[0]=-1; suf[n]=-1;
        for(int i=0;i<n;i++) pre[i+1]=Math.max(pre[i],depth.get(i));
        for(int i=n-1;i>=0;i--) suf[i]=Math.max(suf[i+1],depth.get(i));
        int[] ans=new int[queries.length];
        for(int i=0;i<queries.length;i++) ans[i]=Math.max(pre[tin.get(queries[i])],suf[tout.get(queries[i])]);
        return ans;
    }
}
```

**Key logic / correctness invariant**

Use preorder entry indices and exclusive exit indices. A subtree occupies [tin,tout); max depth outside it equals max(prefix[tin],suffix[tout]). Iterative enter/exit events avoid stack overflow.

**Complexity**

- Time: O(n+q).
- Space: O(n) auxiliary plus O(q) output.

### LC 834 — Question 58/58

**Problem statement**

Given an undirected connected tree with n nodes labeled 0 through n−1 and n−1 edges, return an array where ans[i] equals the sum of distances in edges from i to every node.

**Examples**

1. n=6, edges=[[0,1],[0,2],[2,3],[2,4],[2,5]] → [8,12,6,10,10,10]
2. n=1, edges=[] → [0]

**Constraints**

1–30,000 nodes; n−1 unique undirected edges; connected acyclic graph.

**Why this belongs to the family**

Need answer for every possible root, so calculate one root then transfer across each edge.

**Exact implementation evolution**

Foundation of this subpattern. postorder derives sizes and root distance sum; preorder transfers result to child in O(1).

**Complete Java solution**

```java
import java.util.*;

class Solution {
    public int[] sumOfDistancesInTree(int n,int[][] edges) {
        List<List<Integer>> g=new ArrayList<>(); for(int i=0;i<n;i++) g.add(new ArrayList<>());
        for(int[] e:edges) {g.get(e[0]).add(e[1]); g.get(e[1]).add(e[0]);}
        int[] parent=new int[n],order=new int[n],size=new int[n],ans=new int[n];
        Arrays.fill(parent,-1); Arrays.fill(size,1); order[0]=0; int count=1;
        for(int i=0;i<count;i++) {
            int u=order[i];
            for(int v:g.get(u)) if(v!=parent[u]) {parent[v]=u; order[count++]=v;}
        }
        for(int i=n-1;i>0;i--) {int u=order[i]; size[parent[u]]+=size[u]; ans[0]+=size[u];}
        for(int i=1;i<n;i++) {int u=order[i]; ans[u]=ans[parent[u]]+n-2*size[u];}
        return ans;
    }
}
```

**Key logic / correctness invariant**

Build a parent-first traversal order. Reverse it to aggregate subtree sizes and root-distance sum; traverse forward to apply ans[child]=ans[parent]+n−2*size[child].

**Complexity**

- Time: O(n).
- Space: O(n).

<a id="companion-concepts"></a>
## Companion concepts and implementation caveats

- **Full, perfect, complete:** Full means every node has zero or two children; perfect additionally requires all leaves at the same depth; complete means levels fill left-to-right with no gaps. LC 116/2415 rely on perfect trees; LC 958 tests completeness.
- **Height conventions:** Null height = 0 in node-count height; leaf height = 1. Edge-count height = node-count height − 1 for nonempty trees. LC 543 and LC 2458 return edge measures, not node counts.
- **Traversal orders:** Preorder processes root-left-right (construction, serialization); inorder processes left-root-right (BST stream); postorder processes left-right-root (height, pruning, tree DP). BFS processes each level before its children.
- **Iterative DFS:** A preorder stack pushes right before left. An inorder stack repeatedly pushes the left spine, pops/visits, then moves right. For postorder, use enter/exit frames or a stack with a visited state. Explicit stacks avoid JVM call-stack limits.
- **Morris inorder:** Temporarily link the rightmost node of the left subtree to its ancestor, descend left, and restore the link when encountered again. This yields O(n) time/O(1) auxiliary space; the tree must not be concurrently traversed or mutated. LC 99 can use this for its constant-space follow-up.
- **Pointer identity:** LCA and parent-map traversals use node identity, not value equality. A standard LeetCode TreeNode does not override equals/hashCode.
- **Overflow:** LC 437 uses long prefixes, LC 662 normalizes long position indices, LC 637 uses long sums, and strict BST checks use long bounds to avoid integer sentinel collisions.
- **Recursion caveat:** The canonical recursive solutions retain the master plan's pedagogical progression. Deeply skewed trees can exhaust the JVM call stack, especially at the 100,000-node bounds of LC 111, 1448 and 236. For production or adversarial inputs use explicit-stack DFS or BFS. Sample tests do not establish maximum-depth safety. LC 2385, 2096, 2458 and 834 use iterative traversal to avoid that risk.
- **Optimization scope:** LC 572 intentionally uses the locked pairwise DFS strategy rather than an asymptotically faster serialization matcher; LC 2415 intentionally uses BFS rather than mirror DFS; LC 114 uses reverse-preorder recursion rather than its O(1) rewiring follow-up. This preserves the intended solution evolution.
- **Further advanced concepts:** Binary lifting, heavy-light decomposition and centroid decomposition are outside the locked 58-question practice sequence. No extra question IDs have been inserted.

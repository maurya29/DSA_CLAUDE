## Subpattern RQ1: Fenwick point updates and prefix/range sums

**When to Apply:**

Mutable point values, repeated prefix or rectangle sums; accumulate disjoint lowbit blocks. Use one-based indices for updates; never update index zero. prefix(r)-prefix(l-1) gives a one-based inclusive interval. Each loop visits disjoint blocks or their ancestors.

**Basic Java Code Snippet:**

```java
void add(int[] bit,int i,int delta) {
    for(;i<bit.length;i+=i&-i) bit[i]+=delta;
}
int prefix(int[] bit,int i) {
    int s=0; for(;i>0;i-=i&-i) s+=bit[i]; return s;
}
```

**Core Logic:**

Use one-based indices for updates; never update index zero. prefix(r)-prefix(l-1) gives a one-based inclusive interval. Each loop visits disjoint blocks or their ancestors.

### LeetCode 307

**Question:**

Implement NumArray for an integer array. update(index,val) replaces the element at the given zero-based index. sumRange(left,right) returns the sum of the inclusive interval in the current array. Calls may be interleaved arbitrarily.

**Examples:**

[1,3,5]: sumRange(0,2) → 9; update(1,2); sumRange(0,2) → 8.

[-2]: sumRange(0,0) → -2; update(0,7); sumRange(0,0) → 7.

**Constraints:**

1 ≤ n ≤ 30,000; -100 ≤ nums[i], val ≤ 100; 0 ≤ left ≤ right < n; at most 30,000 update/query calls.

**Why This Subpattern Applies:**

Mutable point values, repeated prefix or rectangle sums; accumulate disjoint lowbit blocks.  Mutable 1D point assignment and inclusive sum queries; Fenwick tree of deltas with sum(r+1)-sum(l), O(log n) each.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class NumArray {
    private final int[] a, bit;
    public NumArray(int[] nums) {
        a = nums.clone(); bit = new int[a.length + 1];
        for (int i = 1; i < bit.length; i++) {
            bit[i] += a[i - 1];
            int p = i + (i & -i);
            if (p < bit.length) bit[p] += bit[i];
        }
    }
    public void update(int index, int val) {
        int delta = val - a[index]; a[index] = val;
        for (int i = index + 1; i < bit.length; i += i & -i) bit[i] += delta;
    }
    private int prefix(int i) {
        int sum = 0;
        for (; i > 0; i -= i & -i) sum += bit[i];
        return sum;
    }
    public int sumRange(int left, int right) {
        return prefix(right + 1) - prefix(left);
    }
}
```

**Key Logic:**

Each BIT cell contains the sum of a lowbit-sized block ending at its one-based index. Build propagates each completed block to its parent. Assignment becomes a delta; prefix queries remove the last block repeatedly. Subtraction cancels the prefix outside the requested interval.

**Time Complexity:** O(n) construction, O(log n) per operation.

**Space Complexity:** O(n) persistent storage; O(1) auxiliary per operation.

### LeetCode 308

**Question:**

Implement NumMatrix for a nonempty integer matrix. update(row,col,val) replaces one cell. sumRegion(row1,col1,row2,col2) returns the sum of the inclusive rectangle with the given top-left and bottom-right corners, reflecting every prior update.

**Examples:**

[[1,2],[3,4]]: sumRegion(0,0,1,1) → 10; update(0,1,5); sumRegion(0,1,1,1) → 9.

[[4]]: update(0,0,-2); sumRegion(0,0,0,0) → -2.

**Constraints:**

1 ≤ rows, cols ≤ 200; -100,000 ≤ matrix[i][j], val ≤ 100,000; valid ordered rectangle corners; at most 5,000 calls to update and sumRegion.

**Why This Subpattern Applies:**

Mutable point values, repeated prefix or rectangle sums; accumulate disjoint lowbit blocks.  Mutable 2D point assignment and rectangle sums; 2D Fenwick tree, inclusion-exclusion of four prefix rectangles, O(log rows · log cols) per operation. (Premium access may be required.)

**Connection to Previous Solution:**

Generalize each BIT index and lowbit loop to nested row/column loops; replace two-prefix difference by four-prefix inclusion-exclusion.

**Java Solution:**

```java
class NumMatrix {
    private final int[][] a;
    private final long[][] bit;
    private final int m,n;
    public NumMatrix(int[][] matrix) {
        m=matrix.length; n=matrix[0].length;
        a=new int[m][n]; bit=new long[m+1][n+1];
        for(int i=0;i<m;i++) for(int j=0;j<n;j++) update(i,j,matrix[i][j]);
    }
    public void update(int row,int col,int val) {
        long d=(long)val-a[row][col]; a[row][col]=val;
        for(int i=row+1;i<=m;i+=i&-i)
            for(int j=col+1;j<=n;j+=j&-j) bit[i][j]+=d;
    }
    private long prefix(int r,int c) {
        long s=0;
        for(int i=r;i>0;i-=i&-i)
            for(int j=c;j>0;j-=j&-j) s+=bit[i][j];
        return s;
    }
    public int sumRegion(int r1,int c1,int r2,int c2) {
        return (int)(prefix(r2+1,c2+1)-prefix(r1,c2+1)
            -prefix(r2+1,c1)+prefix(r1,c1));
    }
}
```

**Key Logic:**

Each cell aggregates a Cartesian product of two lowbit blocks. Nested updates touch every ancestor rectangle. Inclusion–exclusion subtracts the top and left strips and restores their overlap. Long intermediates avoid overflow; the judge API returns int.

**Time Complexity:** O(mn log(m+1) log(n+1)) construction; O(log(m+1) log(n+1)) per operation.

**Space Complexity:** O(mn) storage; O(1) auxiliary per operation.

## Subpattern RQ2: Fenwick frequency ranks and order counting

**When to Apply:**

Elements arrive in an order; query how many earlier keys are smaller/greater. The axis is ordered values, not array indices. Count strict lower and upper ranks before recording the current event; duplicates must share a rank.

**Basic Java Code Snippet:**

```java
long insertionCost(int[] bit,int rank,int seen) {
    int less=0, atMost=0;
    for(int i=rank-1;i>0;i-=i&-i) less+=bit[i];
    for(int i=rank;i>0;i-=i&-i) atMost+=bit[i];
    for(int i=rank;i<bit.length;i+=i&-i) bit[i]++;
    return Math.min(less,seen-atMost);
}
```

**Core Logic:**

The axis is ordered values, not array indices. Count strict lower and upper ranks before recording the current event; duplicates must share a rank.

### LeetCode 1649

**Question:**

Insert the values of instructions in their given order into an initially empty sorted multiset. Inserting x costs the smaller of the number of previously inserted values strictly less than x and strictly greater than x. Equal values do not contribute. Return total cost modulo 1,000,000,007.

**Examples:**

[1,5,6,2] → 1 (the last insertion costs 1).

[1,2,3,6,5,4] → 3.

[2,2,2] → 0.

**Constraints:**

1 ≤ instructions.length ≤ 100,000; 1 ≤ instructions[i] ≤ 100,000.

**Why This Subpattern Applies:**

Elements arrive in an order; query how many earlier keys are smaller/greater.  Stream values into a bounded-coordinate frequency BIT; cost at each insertion is min(countLess, countGreater), accumulated modulo 1e9+7.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    private int[] bit;
    private void add(int i,int d) {
        for(;i<bit.length;i+=i&-i) bit[i]+=d;
    }
    private int sum(int i) {
        int s=0; for(;i>0;i-=i&-i) s+=bit[i]; return s;
    }
    public int createSortedArray(int[] instructions) {
        int max=0; for(int x:instructions) max=Math.max(max,x);
        bit=new int[max+1]; long ans=0; int seen=0;
        for(int x:instructions) {
            ans+=Math.min(sum(x-1),seen-sum(x));
            add(x,1); seen++;
        }
        return (int)(ans%1_000_000_007);
    }
}
```

**Key Logic:**

Query before inserting so only earlier values count. The prefix ending at x includes equal values, so subtracting it from seen counts strictly greater values.

**Time Complexity:** O(n log(V+1) + V), where V is maximum value.

**Space Complexity:** O(V) auxiliary.

### LeetCode 2179

**Question:**

Given two permutations nums1 and nums2 of the integers 0 through n-1, count triples of distinct values (x,y,z) whose positions are strictly increasing in both permutations. Return the number of such triples as a long.

**Examples:**

[2,0,1,3], [0,1,2,3] → 1.

[0,1,2], [0,1,2] → 1.

[0,1,2], [2,1,0] → 0.

**Constraints:**

3 ≤ n ≤ 100,000; both arrays are permutations of [0,n-1].

**Why This Subpattern Applies:**

Elements arrive in an order; query how many earlier keys are smaller/greater.  Map values in one permutation to their positions in another; compute smaller positions on left and larger on right using BIT, sum products.

**Connection to Previous Solution:**

Retain prefix-frequency rank queries; transform items into permutation ranks and replace per-item minimum with leftCount * rightCount (using two directional sweeps or total-left counts).

**Java Solution:**

```java
class Solution {
    private int[] bit;
    private void add(int i,int d) {
        for(;i<bit.length;i+=i&-i) bit[i]+=d;
    }
    private int sum(int i) {
        int s=0; for(;i>0;i-=i&-i) s+=bit[i]; return s;
    }
    public long goodTriplets(int[] nums1,int[] nums2) {
        int n=nums1.length; int[] pos=new int[n]; bit=new int[n+1];
        for(int i=0;i<n;i++) pos[nums2[i]]=i+1;
        long ans=0;
        for(int i=0;i<n;i++) {
            int r=pos[nums1[i]], left=sum(r-1);
            int right=n-r-(i-left);
            ans+=(long)left*right; add(r,1);
        }
        return ans;
    }
}
```

**Key Logic:**

Map each value to its one-based position in nums2. For a middle element, left counts earlier smaller ranks. Of all n-r greater ranks, i-left have already appeared; the rest are on the right. Every valid triple has exactly one middle element.

**Time Complexity:** O(n log n).

**Space Complexity:** O(n) auxiliary.

### LeetCode 2031

**Question:**

Given a binary array nums, count nonempty contiguous subarrays containing strictly more ones than zeros. Return the count modulo 1,000,000,007.

**Examples:**

[0,1,1,0,1] → 9.

[0] → 0.

[1,1] → 3.

**Constraints:**

1 ≤ n ≤ 100,000; nums[i] is 0 or 1. Premium access may be required.

**Why This Subpattern Applies:**

Elements arrive in an order; query how many earlier keys are smaller/greater.  Convert 0 to -1 and 1 to +1; count earlier prefix sums strictly below current prefix using coordinate-compressed BIT, modulo 1e9+7.

**Connection to Previous Solution:**

Replace permutation-rank events with signed cumulative balances; coordinate-compress prefix states, seed prefix zero, and query ranks strictly less than current state.

**Java Solution:**

```java
class Solution {
    private int[] bit;
    private void add(int i,int d) {
        for(;i<bit.length;i+=i&-i) bit[i]+=d;
    }
    private int sum(int i) {
        int s=0; for(;i>0;i-=i&-i) s+=bit[i]; return s;
    }
    public int subarraysWithMoreZerosThanOnes(int[] nums) {
        int n=nums.length, rank=n+1; bit=new int[2*n+2];
        add(rank,1); long ans=0;
        for(int x:nums) {
            rank+=x==1?1:-1;
            ans+=sum(rank-1); add(rank,1);
        }
        return (int)(ans%1_000_000_007);
    }
}
```

**Key Logic:**

A subarray has more ones exactly when its ending balance exceeds its starting balance. The empty prefix is inserted first. Balances lie in [-n,n], so shifting by n+1 is a direct rank mapping instead of sorting compressed keys. The judge method name is counterintuitive: the required condition is more ones than zeros.

**Time Complexity:** O(n log n).

**Space Complexity:** O(n) auxiliary.

## Subpattern RQ3: Fenwick active-position order statistics

**When to Apply:**

Positions are removed over time; rank among surviving positions determines cost or order. Start with all positions active. Prefix rank gives the number of surviving elements before a chosen position; remove it by decrementing its ancestors.

**Basic Java Code Snippet:**

```java
int[] activeTree(int n) {
    int[] bit=new int[n+1];
    for(int i=1;i<=n;i++) bit[i]=i&-i;
    return bit;
}
int removeAndCountBefore(int[] bit,int rank) {
    int count=0;
    for(int i=rank-1;i>0;i-=i&-i) count+=bit[i];
    for(int i=rank;i<bit.length;i+=i&-i) bit[i]--;
    return count;
}
```

**Core Logic:**

Start with all positions active. Prefix rank gives the number of surviving elements before a chosen position; remove it by decrementing its ancestors.

### LeetCode 2659

**Question:**

Given an array of distinct integers, repeatedly perform one operation until empty: if the first value is the smallest remaining value, delete it; otherwise move the first value to the end. Return the total number of operations.

**Examples:**

[3,4,-1] → 5.

[1,2,4,3] → 5.

[1,2,3] → 3.

**Constraints:**

1 ≤ n ≤ 100,000; -10^9 ≤ nums[i] ≤ 10^9; all values distinct.

**Why This Subpattern Applies:**

Positions are removed over time; rank among surviving positions determines cost or order.  Sort (value,index) for deletion order; BIT marks active positions, calculate circular surviving distance to next removed index.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
import java.util.Arrays;
class Solution {
    private int[] bit;
    private void add(int i,int d) {
        for(;i<bit.length;i+=i&-i) bit[i]+=d;
    }
    private int sum(int i) {
        int s=0; for(;i>0;i-=i&-i) s+=bit[i]; return s;
    }
    public long countOperationsToEmptyArray(int[] nums) {
        int n=nums.length; bit=new int[n+1]; long[] order=new long[n];
        for(int i=1;i<=n;i++) {
            bit[i]=i&-i;
            order[i-1]=((long)nums[i-1]<<32)|(i-1L);
        }
        Arrays.sort(order); int prev=0; long ans=0;
        for(long entry:order) {
            int r=(int)entry+1;
            if(r>prev) ans+=sum(r)-sum(prev);
            else ans+=sum(n)-sum(prev)+sum(r);
            add(r,-1); prev=r;
        }
        return ans;
    }
}
```

**Key Logic:**

Sorting fixes deletion order. The BIT marks surviving original positions. Starting just after the previous deleted index, count active elements through the target, wrapping when necessary. That count includes the deletion operation. Encoding signed value in the high bits preserves numeric sorting.

**Time Complexity:** O(n log n).

**Space Complexity:** O(n) auxiliary.

### LeetCode 1505

**Question:**

Given a decimal string num and an integer k, perform at most k swaps of adjacent digits. Return the lexicographically smallest string obtainable, preserving length and allowing leading zeros.

**Examples:**

num="4321", k=4 → "1342".

num="100", k=1 → "010".

num="36789", k=1000 → "36789".

**Constraints:**

1 ≤ num.length ≤ 30,000; 1 ≤ k ≤ 10^9; num contains decimal digits.

**Why This Subpattern Applies:**

Positions are removed over time; rank among surviving positions determines cost or order.  To minimize decimal text under at most k adjacent swaps, greedily choose earliest feasible smallest digit via per-digit index queues and BIT ranks of earlier removed positions.

**Connection to Previous Solution:**

Reuse BIT of active/removed position ranks and removal updates; replace predetermined deletion order with smallest-affordable digit selection and deduct its current-rank swap cost.

**Java Solution:**

```java
import java.util.*;
class Solution {
    private int[] bit;
    private void add(int i,int d) {
        for(;i<bit.length;i+=i&-i) bit[i]+=d;
    }
    private int sum(int i) {
        int s=0; for(;i>0;i-=i&-i) s+=bit[i]; return s;
    }
    public String minInteger(String num,int k) {
        int n=num.length();
        return build(num,k,n);
    }
    private String build(String num,int k,int n) {
        bit=new int[n+1];
        List<ArrayDeque<Integer>> queues=new ArrayList<>(10);
        for(int d=0;d<10;d++) queues.add(new ArrayDeque<>());
        for(int i=0;i<n;i++) { queues.get(num.charAt(i)-'0').add(i+1); bit[i+1]=(i+1)&-(i+1); }
        StringBuilder out=new StringBuilder(n);
        for(int i=0;i<n;i++) for(int d=0;d<10;d++) {
            var q=queues.get(d); if(q.isEmpty()) continue;
            int p=q.peek(), cost=sum(p-1);
            if(cost<=k) {
                k-=cost; out.append((char)('0'+d)); q.remove(); add(p,-1); break;
            }
        }
        return out.toString();
    }
}
```

**Key Logic:**

Each queue keeps original positions for one digit. Only its earliest unused occurrence can be cheapest. The number of still-active positions before it equals adjacent swaps needed. Greedily take the smallest affordable digit; at least the first active digit costs zero.

**Time Complexity:** O(10n log n) = O(n log n).

**Space Complexity:** O(n) auxiliary and O(n) output.

## Subpattern RQ4: Fenwick maintenance of local predicates

**When to Apply:**

One edit changes only a constant number of locally defined indicators, while queries aggregate those indicators over ranges. After editing a value, refresh only predicates whose neighborhoods include it. Query the indicator tree rather than rescanning the interval.

**Basic Java Code Snippet:**

```java
void refresh(int[] a,int[] flags,int[] bit,int index) {
    for(int j=Math.max(1,index-1);j<=Math.min(a.length-2,index+1);j++) {
        int v=a[j]>a[j-1]&&a[j]>a[j+1]?1:0;
        int d=v-flags[j]; flags[j]=v;
        for(int i=j+1;i<bit.length;i+=i&-i) bit[i]+=d;
    }
}
```

**Core Logic:**

After editing a value, refresh only predicates whose neighborhoods include it. Query the indicator tree rather than rescanning the interval.

### LeetCode 3187

**Question:**

Given nums and queries, a peak is an interior index whose value is strictly greater than both neighbors. Query [1,l,r] asks how many peaks lie strictly inside nums[l..r], excluding its endpoints. Query [2,index,val] assigns nums[index]=val. Return answers for type 1 queries in order.

**Examples:**

nums=[3,1,4,2,5], queries=[[1,0,4],[2,3,6],[1,0,4]] → [1,1].

nums=[1,2,1], queries=[[1,0,2],[2,1,1],[1,0,2]] → [1,0].

**Constraints:**

3 ≤ n ≤ 100,000; 1 ≤ nums[i], val ≤ 100,000; 1 ≤ queries.length ≤ 100,000; valid indices, l ≤ r.

**Why This Subpattern Applies:**

One edit changes only a constant number of locally defined indicators, while queries aggregate those indicators over ranges.  Maintain whether each interior element is a peak; point update changes only indices i-1,i,i+1, BIT answers peak counts strictly inside queried endpoints.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
import java.util.*;
class Solution {
    private int[] bit;
    private void add(int i,int d) {
        for(;i<bit.length;i+=i&-i) bit[i]+=d;
    }
    private int sum(int i) {
        int s=0; for(;i>0;i-=i&-i) s+=bit[i]; return s;
    }
    private int peak(int[] a,int i) {
        return i>0&&i+1<a.length&&a[i]>a[i-1]&&a[i]>a[i+1]?1:0;
    }
    public List<Integer> countOfPeaks(int[] nums,int[][] queries) {
        int n=nums.length; bit=new int[n+1]; int[] flags=new int[n];
        for(int i=1;i<n-1;i++) { flags[i]=peak(nums,i); add(i+1,flags[i]); }
        List<Integer> ans=new ArrayList<>();
        for(int[] q:queries) {
            if(q[0]==1) ans.add(q[2]-q[1]<2?0:sum(q[2])-sum(q[1]+1));
            else {
                int i=q[1]; nums[i]=q[2];
                for(int j=Math.max(1,i-1);j<=Math.min(n-2,i+1);j++) {
                    int v=peak(nums,j); add(j+1,v-flags[j]); flags[j]=v;
                }
            }
        }
        return ans;
    }
}
```

**Key Logic:**

Only three peak predicates depend on an edited position. Store each old flag to compute the delta. The interior interval is [l+1,r-1]; intervals shorter than three elements have zero peaks.

**Time Complexity:** O((n+q) log n).

**Space Complexity:** O(n) auxiliary plus O(q) output.


**Core Logic:**

### LeetCode 2926

**Question:**

Choose a nonempty subsequence with increasing indices i0,i1,... such that for every consecutive pair nums[ij]-nums[ij-1] ≥ ij-ij-1. Return the maximum possible sum of its elements; a singleton is always valid.

**Examples:**

[3,3,5,6] → 14.

[5,-1,-3,8] → 13.

[-2,-1] → -1.

**Constraints:**

1 ≤ n ≤ 100,000; -10^9 ≤ nums[i] ≤ 10^9.

**Why This Subpattern Applies:**

DP transition asks for best earlier state among values meeting a monotone key boundary.  Sort/compress keys nums[i]-i; Fenwick prefix maximum stores best balanced-subsequence sum at each key; query key <= current then update best.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
import java.util.Arrays;
class Solution {
    public long maxBalancedSubsequenceSum(int[] nums) {
        int n=nums.length; long[] keys=new long[n];
        for(int i=0;i<n;i++) keys[i]=(long)nums[i]-i;
        long[] sorted=keys.clone(); Arrays.sort(sorted);
        long[] bit=new long[n+1]; long ans=Long.MIN_VALUE;
        for(int i=0;i<n;i++) {
            int r=Arrays.binarySearch(sorted,keys[i])+1;
            long best=0;
            for(int j=r;j>0;j-=j&-j) best=Math.max(best,bit[j]);
            long dp=best+nums[i]; ans=Math.max(ans,dp);
            for(int j=r;j<=n;j+=j&-j) bit[j]=Math.max(bit[j],dp);
        }
        return ans;
    }
}
```

**Key Logic:**

```java
class BookMyShow {
    private final int n,m;
    private final long[] sum;
    private final int[] max;
    private final boolean[] cleared;
    public BookMyShow(int n,int m) {
        this.n=n; this.m=m; sum=new long[4*n]; max=new int[4*n]; cleared=new boolean[4*n]; build(1,0,n-1);
    }
    private void build(int p,int l,int r) {
        sum[p]=(long)(r-l+1)*m; max[p]=m;
        if(l<r) {int mid=(l+r)>>>1; build(p*2,l,mid); build(p*2+1,mid+1,r);}
    }
    private void clear(int p) {sum[p]=0; max[p]=0; cleared[p]=true;}
    private void push(int p) {if(cleared[p]) {clear(p*2); clear(p*2+1); cleared[p]=false;}}
    private void pull(int p) {sum[p]=sum[p*2]+sum[p*2+1]; max[p]=Math.max(max[p*2],max[p*2+1]);}
    private long prefix(int p,int l,int r,int end) {
        if(l>end||sum[p]==0) return 0;
        if(r<=end) return sum[p];
        int mid=(l+r)>>>1; return prefix(p*2,l,mid,end)+prefix(p*2+1,mid+1,r,end);
    }
    private int first(int p,int l,int r,int k,int end) {
        if(l>end||max[p]<k) return -1;
        if(l==r) return l;
        int mid=(l+r)>>>1,x=first(p*2,l,mid,k,end);
        return x>=0?x:first(p*2+1,mid+1,r,k,end);
    }
    private int take(int p,int l,int r,int row,int k) {
        if(l==r) {int seat=m-max[p]; max[p]-=k; sum[p]-=k; return seat;}
        push(p); int mid=(l+r)>>>1;
        int seat=row<=mid?take(p*2,l,mid,row,k):take(p*2+1,mid+1,r,row,k);
        pull(p); return seat;
    }
    private void consume(int p,int l,int r,long k) {
        if(k==0) return;
        if(sum[p]==k) {clear(p); return;}
        if(l==r) {sum[p]-=k; max[p]=(int)sum[p]; return;}
        push(p); int mid=(l+r)>>>1;
        long left=Math.min(k,sum[p*2]);
        consume(p*2,l,mid,left); consume(p*2+1,mid+1,r,k-left); pull(p);
    }
    public int[] gather(int k,int maxRow) {
        int row=first(1,0,n-1,k,maxRow);
        return row<0?new int[0]:new int[]{row,take(1,0,n-1,row,k)};
    }
    public boolean scatter(int k,int maxRow) {
        if(prefix(1,0,n-1,maxRow)<k) return false;
        consume(1,0,n-1,k); return true;
    }
}
```

**Key Logic:**

Every row retains a contiguous free suffix because allocation always starts at its first free seat. Sum checks scatter feasibility without mutation; max prunes gather searches. Scatter can clear whole subtrees at once with a lazy zero tag; after the prefix feasibility check, consuming the globally earliest k free seats cannot pass maxRow. Only one partially consumed branch exists at each level. A cleared node has zero aggregate, so read-only searches never descend into stale children.

**Time Complexity:** O(n) build; O(log(n+1)) per gather or scatter, including the prefix check.

**Space Complexity:** O(n) storage, O(log n) recursion stack.

```java
class Solution {
    private int[] tree,tag;

        if(a<=l&&r<=b) return tree[p];

        return Math.max(max(p*2,l,m,a,b),max(p*2+1,m+1,r,a,b));
    }
    private void set(int p,int l,int r,int a,int b,int v) {
        if(b<l||r<a) return;
        if(a<=l&&r<=b) {apply(p,v); return;}
        push(p); int m=(l+r)>>>1;
        set(p*2,l,m,a,b,v); set(p*2+1,m+1,r,a,b,v);
        tree[p]=Math.max(tree[p*2],tree[p*2+1]);
    }

        for(int[] a:positions) {

        }
        return ans;
    }
}
```

Compress endpoints into elementary half-open spans. The support height is the maximum among covered spans, and the new top is that maximum plus side. The entire footprint gets the new height. Lazy assignment replaces any previous assignment; zero safely represents no pending tag because assigned heights are positive.

```java
class Solution {
    private int[] len,pref,suff,best;
    private char[] first,last;
    private void leaf(int p,char c) {len[p]=pref[p]=suff[p]=best[p]=1; first[p]=last[p]=c;}
    private void pull(int p) {
        int a=p*2,b=a+1; len[p]=len[a]+len[b]; first[p]=first[a]; last[p]=last[b];
        pref[p]=pref[a]; suff[p]=suff[b]; best[p]=Math.max(best[a],best[b]);
        if(last[a]==first[b]) {
            best[p]=Math.max(best[p],suff[a]+pref[b]);
            if(pref[a]==len[a]) pref[p]+=pref[b];
            if(suff[b]==len[b]) suff[p]+=suff[a];
        }
    }
    private void build(int p,int l,int r,String s) {
        if(l==r) {leaf(p,s.charAt(l)); return;}
        int m=(l+r)>>>1; build(p*2,l,m,s); build(p*2+1,m+1,r,s); pull(p);
    }
    private void set(int p,int l,int r,int i,char c) {
        if(l==r) {leaf(p,c); return;}
        int m=(l+r)>>>1;
        if(i<=m) set(p*2,l,m,i,c); else set(p*2+1,m+1,r,i,c); pull(p);

        int n=s.length(),z=4*n;
        len=new int[z]; pref=new int[z]; suff=new int[z]; best=new int[z]; first=new char[z]; last=new char[z];

    }
}
```

**Key Logic:**

```java
class Solution {
    private static final long NEG=Long.MIN_VALUE/4, MOD=1_000_000_007L;
    private long[][] dp;
    private void leaf(int p,int v) {dp[p][0]=0; dp[p][1]=dp[p][2]=NEG; dp[p][3]=v;}
    private void pull(int p) {
        long[] a=dp[p*2], b=dp[p*2+1], c=dp[p];
        for(int l=0;l<2;l++) for(int r=0;r<2;r++) {
            long best=NEG;
            for(int x=0;x<2;x++) for(int y=0;y<2;y++) {
                if(x==1&&y==1) continue;
                long u=a[2*l+x],v=b[2*y+r];
                if(u!=NEG&&v!=NEG) best=Math.max(best,u+v);
            }
            c[2*l+r]=best;
        }
    }
    private void build(int p,int l,int r,int[] nums) {
        if(l==r) {leaf(p,nums[l]); return;}
        int m=(l+r)>>>1; build(p*2,l,m,nums); build(p*2+1,m+1,r,nums); pull(p);
    }
    private void set(int p,int l,int r,int i,int v) {
        if(l==r) {leaf(p,v); return;}
        int m=(l+r)>>>1;
        if(i<=m) set(p*2,l,m,i,v); else set(p*2+1,m+1,r,i,v); pull(p);
    }
    public int maximumSumSubsequence(int[] nums,int[][] queries) {
        int n=nums.length; dp=new long[4*n][4]; build(1,0,n-1,nums); long ans=0;
        for(int[] q:queries) {
            set(1,0,n-1,q[0],q[1]); long best=0;
            for(long v:dp[1]) best=Math.max(best,v);
            ans=(ans+best)%MOD;
        }
        return (int)ans;
    }
}
```

**Key Logic:**

State 2*l+r records the maximum sum when the outermost positions are selected exactly as l and r indicate. A singleton has only states 00 and 11. Merge all internal boundary choices except selecting both adjacent boundary positions. Invalid states cannot participate. The root maximum includes the empty choice; use long for unmodded maxima and apply modulo only when accumulating answers.

**Time Complexity:** O(n+q log(n+1)), with constant-size state merges.

```java
class Solution {

    private long[] length;
```

```java
class MajorityChecker {
    private final java.util.Map<Integer,java.util.List<Integer>> positions=new java.util.HashMap<>();
    private void index(int[] arr) {
        for(int i=0;i<arr.length;i++) positions.computeIfAbsent(arr[i],k->new java.util.ArrayList<>()).add(i);
    }
    private int lower(java.util.List<Integer> list,int target) {
        int l=0,r=list.size();
        while(l<r) {int m=(l+r)>>>1; if(list.get(m)<target) l=m+1; else r=m;}
        return l;
    }
    private int frequency(int value,int left,int right) {
        var list=positions.get(value);
        return list==null?0:lower(list,right+1)-lower(list,left);
    }
    private record Vote(int value,int count) {}
    private static final Vote EMPTY=new Vote(0,0);
    private final Vote[] tree;
    private final int n;
    private Vote merge(Vote a,Vote b) {
        if(a.count()==0) return b;
        if(b.count()==0) return a;
        if(a.value()==b.value()) return new Vote(a.value(),a.count()+b.count());
        if(a.count()==b.count()) return EMPTY;
        return a.count()>b.count()?new Vote(a.value(),a.count()-b.count()):new Vote(b.value(),b.count()-a.count());
    }
    public MajorityChecker(int[] arr) {
        index(arr); n=arr.length; tree=new Vote[4*n]; build(1,0,n-1,arr);
    }
    private void build(int p,int l,int r,int[] arr) {
        if(l==r) {tree[p]=new Vote(arr[l],1); return;}
        int m=(l+r)>>>1; build(p*2,l,m,arr); build(p*2+1,m+1,r,arr); tree[p]=merge(tree[p*2],tree[p*2+1]);
    }
    private Vote candidate(int p,int l,int r,int a,int b) {
        if(b<l||r<a) return EMPTY;
        if(a<=l&&r<=b) return tree[p];
        int m=(l+r)>>>1;
        return merge(candidate(p*2,l,m,a,b),candidate(p*2+1,m+1,r,a,b));
    }
    public int query(int left,int right,int threshold) {
        Vote v=candidate(1,0,n-1,left,right);
        return v.count()>0&&frequency(v.value(),left,right)>=threshold?v.value():-1;
    }
}
```

**Key Logic:**

Cancel pairs of different values. A strict majority cannot be eliminated by any sequence of such cancellations, so the candidate obtained by merging segment summaries must be that majority if one exists. The residual vote count is not its actual frequency; use the previous solution’s binary searches to verify the exact threshold. Cancellation summaries need not be strictly associative when no majority exists, but any merge grouping preserves a true majority.

**Time Complexity:** O(n) expected construction; O(log n) range candidate and O(log n) verification per query.

**Space Complexity:** O(n) storage; O(log n) query stack and temporary vote records.

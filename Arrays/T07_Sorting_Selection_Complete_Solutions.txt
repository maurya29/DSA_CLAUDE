## Subpattern R1: Pivot partitioning, full sort → order statistic

**When to Apply:**

- Recognition: order *everything* or find an order statistic without sorting every other element. Invariant: elements before the `lt` boundary are smaller; elements after `gt` are larger; middle matches pivot. For 912, recurse on both outside sections; for 215/973/1985, recurse/iterate only on the target side. Use randomly chosen pivot to avoid systematic bad cases.
- **Recognition clue:** Need all elements ordered without library sort: randomized in-place 3-way quicksort, partition `<pivot`, `==pivot`, `>pivot`; recursively sort both outer partitions; expected O(n log n), worst O(n²), expected O(log n) stack.
- **Central invariant:** the three pivot bands partition every element by comparison with the pivot.

**Basic Java Code Snippet:**

```java
int lt = left, i = left, gt = right;
int pivot = values[left + java.util.concurrent.ThreadLocalRandom.current()
                                    .nextInt(right - left + 1)];
while (i <= gt) {
    if (values[i] < pivot) { int t=values[lt]; values[lt++]=values[i]; values[i++]=t; }
    else if (values[i] > pivot) { int t=values[i]; values[i]=values[gt]; values[gt--]=t; }
    else i++;
}
// [left,lt) < pivot; [lt,gt] == pivot; (gt,right] > pivot.
// Replace < and > with a comparison of derived keys for other data types.
```

**Core Logic:**

Choose a random pivot, classify elements into three contiguous regions, and either recurse on both sides (sort) or only the side containing the target rank (select).

**Questions Covered:** LeetCode 912, LeetCode 215, LeetCode 973, LeetCode 1985

### LeetCode 912

**Question:**

Return the input integer array sorted in nondecreasing order. Implement the sorting algorithm yourself instead of calling a built-in sorting routine. Duplicates and negative numbers must be handled.

**Examples:**

`[5,2,3,1] → [1,2,3,5]`; `[5,1,1,2,0,0] → [0,0,1,1,2,5]`; `[-1,0,-1] → [-1,-1,0]`.

**Constraints:**

1 ≤ n ≤ 5×10⁴; −5×10⁴ ≤ nums[i] ≤ 5×10⁴.

**Why This Subpattern Applies:**

Need all elements ordered without library sort: randomized in-place 3-way quicksort, partition `<pivot`, `==pivot`, `>pivot`; recursively sort both outer partitions; expected O(n log n), worst O(n²), expected O(log n) stack. Explain merge-sort alternative and guaranteed O(n log n) as companion concept.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int[] sortArray(int[] nums) {
        sort(nums, 0, nums.length - 1);
        return nums;
    }
    private void sort(int[] a, int left, int right) {
        while (left < right) {
            int pivot = a[java.util.concurrent.ThreadLocalRandom.current().nextInt(left, right + 1)];
            int lt = left, i = left, gt = right;
            while (i <= gt) {
                if (a[i] < pivot) swap(a, lt++, i++);
                else if (a[i] > pivot) swap(a, i, gt--);
                else i++;
            }
            if (lt - left < right - gt) {
                sort(a, left, lt - 1);
                left = gt + 1;
            } else {
                sort(a, gt + 1, right);
                right = lt - 1;
            }
        }
    }
    private void swap(int[] a, int i, int j) {
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }
}
```

**Key Logic:**

Partition into smaller/equal/larger pivot bands, then sort both outside bands; recurse on smaller band first to limit stack.

**Time Complexity:**

Expected O(n log n); worst O(n²) with unlucky pivots.

**Space Complexity:**

Expected O(log n) recursive stack; O(log n) worst stack with smaller-side recursion and tail iteration.

### LeetCode 215

**Question:**

Find the kth largest element of an unsorted integer array, counting repeated values separately. The kth largest is the element at index n−k in fully ascending order, but you need not produce the entire sorted array.

**Examples:**

`[3,2,1,5,6,4], k=2 → 5`; `[3,2,3,1,2,4,5,5,6], k=4 → 4`; `[1], k=1 → 1`.

**Constraints:**

1 ≤ k ≤ n ≤ 10⁵; −10⁴ ≤ nums[i] ≤ 10⁴.

**Why This Subpattern Applies:**

Need only kth **largest**, not fully ordered data: randomized 3-way quickselect; compare target descending-order rank to equal-pivot interval; expected O(n), worst O(n²).

**Connection to Previous Solution:**

Reuse identical partition primitive; **do not sort both sides**: continue only in the partition containing target rank, or stop when it falls inside equal band.

**Java Solution:**

```java
class Solution {
    public int findKthLargest(int[] nums, int k) {
        int target = nums.length - k, left = 0, right = nums.length - 1;
        while (left <= right) {
            int pivot = nums[java.util.concurrent.ThreadLocalRandom.current().nextInt(left, right + 1)];
            int lt = left, i = left, gt = right;
            while (i <= gt) {
                if (nums[i] < pivot) swap(nums, lt++, i++);
                else if (nums[i] > pivot) swap(nums, i, gt--);
                else i++;
            }
            if (target < lt) right = lt - 1;
            else if (target > gt) left = gt + 1;
            else return nums[target];
        }
        throw new IllegalStateException();
    }
    private void swap(int[] a, int i, int j) {
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }
}
```

**Key Logic:**

Use the same 3-way partition but discard the band that cannot contain the target index.

**Time Complexity:**

Expected O(n); worst O(n²).

**Space Complexity:**

O(1) auxiliary; in-place iterative selection.

### LeetCode 973

**Question:**

Given integer-coordinate points in the plane and integer k, return any k points having the smallest squared distances to the origin. The returned points may be in any order, and ties may be resolved arbitrarily.

**Examples:**

`[[1,3],[-2,2]], k=1 → [[-2,2]]`; `[[3,3],[5,-1],[-2,4]], k=2 → [[3,3],[-2,4]]` (one valid result); `[[0,0],[1,1]], k=2 → both points`.

**Constraints:**

1 ≤ k ≤ n ≤ 10⁴; −10⁴ ≤ each coordinate ≤ 10⁴; answers may be returned in any order.

**Why This Subpattern Applies:**

Need kth smallest *derived key* among objects: 3-way quickselect points by squared Euclidean distance using `long`; return any `k` points from smallest band/side.

**Connection to Previous Solution:**

Keep selective partition, replace scalar comparison with a `long` distance key and change target from kth-largest scalar to first `k` smallest records.

**Java Solution:**

```java
class Solution {
    public int[][] kClosest(int[][] points, int k) {
        int left = 0, right = points.length - 1, target = k - 1;
        while (left <= right) {
            long pivot = distance(points[java.util.concurrent.ThreadLocalRandom.current().nextInt(left, right + 1)]);
            int lt = left, i = left, gt = right;
            while (i <= gt) {
                long d = distance(points[i]);
                if (d < pivot) swap(points, lt++, i++);
                else if (d > pivot) swap(points, i, gt--);
                else i++;
            }
            if (target < lt) right = lt - 1;
            else if (target > gt) left = gt + 1;
            else break;
        }
        return java.util.Arrays.copyOf(points, k);
    }
    private long distance(int[] p) { return (long)p[0] * p[0] + (long)p[1] * p[1]; }
    private void swap(int[][] a, int i, int j) {
        int[] t = a[i]; a[i] = a[j]; a[j] = t;
    }
}
```

**Key Logic:**

Select boundary index k−1 by a derived squared-distance key; all positions before it have no greater distance.

**Time Complexity:**

Expected O(n), worst O(n²), plus O(k) to copy the output.

**Space Complexity:**

O(1) selection auxiliary; O(k) result array of point references.

### LeetCode 1985

**Question:**

An array contains nonnegative integers represented as decimal strings, possibly longer than any primitive numeric type. Return the kth largest occurrence in numeric order; duplicate numeric strings count as separate positions.

**Examples:**

`["3","6","7","10"], k=4 → "3"`; `["2","21","12","1"], k=3 → "2"`; `["0","0","1"], k=2 → "0"`.

**Constraints:**

1 ≤ k ≤ n ≤ 10⁴; 1 ≤ string length ≤ 100; strings are valid canonical nonnegative decimal representations without leading zeros except "0".

**Why This Subpattern Applies:**

Need kth largest arbitrarily large nonnegative **decimal string**, no numeric parsing: quickselect with comparator `(length, lexicographic)` in numeric order, preserving distinct occurrences.

**Connection to Previous Solution:**

Keep select-by-rank and 3-way partition; swap numeric/distance comparison for length-then-lexicographic string comparator and return the selected string.

**Java Solution:**

```java
class Solution {
    public String kthLargestNumber(String[] nums, int k) {
        int target = nums.length - k, left = 0, right = nums.length - 1;
        while (left <= right) {
            String pivot = nums[java.util.concurrent.ThreadLocalRandom.current().nextInt(left, right + 1)];
            int lt = left, i = left, gt = right;
            while (i <= gt) {
                int cmp = compare(nums[i], pivot);
                if (cmp < 0) swap(nums, lt++, i++);
                else if (cmp > 0) swap(nums, i, gt--);
                else i++;
            }
            if (target < lt) right = lt - 1;
            else if (target > gt) left = gt + 1;
            else return nums[target];
        }
        throw new IllegalStateException();
    }
    private int compare(String a, String b) {
        int c = Integer.compare(a.length(), b.length());
        return c != 0 ? c : a.compareTo(b);
    }
    private void swap(String[] a, int i, int j) {
        String t = a[i]; a[i] = a[j]; a[j] = t;
    }
}
```

**Key Logic:**

Numeric ordering follows string length first, then lexicographic order for equal-length strings.

**Time Complexity:**

Expected O(n·L), worst O(n²·L), where L is maximum digit count.

**Space Complexity:**

O(1) auxiliary apart from the input array; comparisons do not copy strings.

## Subpattern R2: Sorting makes adjacent differences informative

**When to Apply:**

- Recognition: the objective is determined by neighbors in the sorted order; non-neighbors cannot improve a minimum gap or cannot contribute a wider consecutive gap.
- **Recognition clue:** All pairs attaining minimum absolute difference: sort, scan adjacent pairs, collect tied minima; O(n log n).
- **Central invariant:** sorted neighbors determine adjacent-gap properties.

**Basic Java Code Snippet:**

```java
java.util.Arrays.sort(a);
for (int i = 1; i < a.length; i++) {
    long gap = (long)a[i] - a[i - 1];
    // check min gap, common gap, or max gap, depending on question
}
```

**Core Logic:**

Sort once, then compare only neighboring sorted keys.

**Questions Covered:** LeetCode 1200, LeetCode 1502, LeetCode 1637

### LeetCode 1200

**Question:**

Find every pair of distinct array elements whose absolute difference equals the smallest difference achievable by any two elements. Return each pair in ascending value order and return the list of pairs ordered by their first element.

**Examples:**

`[4,2,1,3] → [[1,2],[2,3],[3,4]]`; `[1,3,6,10,15] → [[1,3]]`; `[3,8,-10,23,19,-4,-14,27] → [[-14,-10],[19,23],[23,27]]`.

**Constraints:**

2 ≤ n ≤ 10⁵; −10⁶ ≤ arr[i] ≤ 10⁶; elements are distinct.

**Why This Subpattern Applies:**

All pairs attaining minimum absolute difference: sort, scan adjacent pairs, collect tied minima; O(n log n).

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public java.util.List<java.util.List<Integer>> minimumAbsDifference(int[] arr) {
        java.util.Arrays.sort(arr);
        int min = Integer.MAX_VALUE;
        java.util.List<java.util.List<Integer>> result = new java.util.ArrayList<>();
        for (int i = 1; i < arr.length; i++) {
            int gap = arr[i] - arr[i - 1];
            if (gap < min) { min = gap; result.clear(); }
            if (gap == min) result.add(java.util.List.of(arr[i - 1], arr[i]));
        }
        return result;
    }
}
```

**Key Logic:**

After sorting, the closest pair must be adjacent; any nonadjacent pair has at least one intervening value.

**Time Complexity:**

O(n log n) sorting plus O(n) scan.

**Space Complexity:**

O(log n) primitive-array sort stack (implementation-dependent); O(p) output for p pairs.

### LeetCode 1502

**Question:**

Determine whether the elements can be rearranged to form an arithmetic progression, meaning every consecutive pair has the same difference. Return true or false.

**Examples:**

`[3,5,1] → true` (1,3,5); `[1,2,4] → false`; `[7,7,7] → true`.

**Constraints:**

2 ≤ n ≤ 1000; −10⁶ ≤ arr[i] ≤ 10⁶.

**Why This Subpattern Applies:**

Can reordered values form an arithmetic progression: sort, derive first adjacent gap and verify every subsequent gap; O(n log n).

**Connection to Previous Solution:**

Retain sorted adjacent-gap scan; replace global minimum/tied-pair collection with constant required-gap equality check.

**Java Solution:**

```java
class Solution {
    public boolean canMakeArithmeticProgression(int[] arr) {
        java.util.Arrays.sort(arr);
        int gap = arr[1] - arr[0];
        for (int i = 2; i < arr.length; i++)
            if (arr[i] - arr[i - 1] != gap) return false;
        return true;
    }
}
```

**Key Logic:**

Sorted order is the only possible monotone arrangement of a nonconstant arithmetic progression, up to reversal.

**Time Complexity:**

O(n log n).

**Space Complexity:**

O(log n) sorting stack; O(1) explicit auxiliary.

### LeetCode 1637

**Question:**

Points are given by [x,y] coordinates. Find the maximum width of a vertical strip between two x-coordinate boundaries that contains no point strictly inside it. Points on boundaries are allowed; y values do not matter.

**Examples:**

`[[8,7],[9,9],[7,4],[9,7]] → 1`; `[[3,1],[9,0],[1,0],[1,4],[5,3],[8,8]] → 3`; `[[1,1],[1,2]] → 0`.

**Constraints:**

2 ≤ n ≤ 10⁵; 0 ≤ x,y ≤ 10⁹.

**Why This Subpattern Applies:**

Widest empty vertical gap among points: sort by x-coordinate, maximize consecutive x difference; O(n log n).

**Connection to Previous Solution:**

Retain adjacent-gap evaluation; replace 1D scalar elements with point x-key comparator and change all-gaps-equal test into maximum gap objective.

**Java Solution:**

```java
class Solution {
    public int maxWidthOfVerticalArea(int[][] points) {
        java.util.Arrays.sort(points, (a, b) -> Integer.compare(a[0], b[0]));
        int best = 0;
        for (int i = 1; i < points.length; i++)
            best = Math.max(best, points[i][0] - points[i - 1][0]);
        return best;
    }
}
```

**Key Logic:**

Sorting by x makes each candidate empty strip the gap between consecutive x-coordinates.

**Time Complexity:**

O(n log n).

**Space Complexity:**

O(log n) to O(n) sorting overhead depending on object-array sort; no output allocation.

## Subpattern R3: Sorted rank / coordinate compression

**When to Apply:**

- Recognition: preserve original element positions but replace values by their sorted relative order, with explicit duplicate policy.
- **Recognition clue:** Number of array values strictly smaller than each element: sort copy; map each distinct value to its **first sorted index**; emit rank counts in original order; O(n log n).
- **Central invariant:** equal values map to one consistent rank while original positions are retained.

**Basic Java Code Snippet:**

```java
int[] sorted = a.clone();
java.util.Arrays.sort(sorted);
java.util.Map<Integer,Integer> rank = new java.util.HashMap<>();
for (int i = 0, distinct = 0; i < sorted.length; i++) {
    if (i == 0 || sorted[i] != sorted[i - 1]) {
        rank.put(sorted[i], ++distinct); // or assign original index i
    }
}
// Map each original a[i] through rank.
```

**Core Logic:**

Sort a copy, assign the appropriate rank once per distinct value, and map results back.

**Questions Covered:** LeetCode 1365, LeetCode 1331

### LeetCode 1365

**Question:**

For each array element, count how many other array elements have strictly smaller values. Return counts in the original input order; equal values do not count as smaller.

**Examples:**

`[8,1,2,2,3] → [4,0,1,1,3]`; `[6,5,4,8] → [2,1,0,3]`; `[7,7,7] → [0,0,0]`.

**Constraints:**

2 ≤ n ≤ 500; 0 ≤ nums[i] ≤ 100.

**Why This Subpattern Applies:**

Number of array values strictly smaller than each element: sort copy; map each distinct value to its **first sorted index**; emit rank counts in original order; O(n log n).

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int[] smallerNumbersThanCurrent(int[] nums) {
        int[] sorted = nums.clone(), result = new int[nums.length];
        java.util.Arrays.sort(sorted);
        java.util.Map<Integer, Integer> first = new java.util.HashMap<>();
        for (int i = 0; i < sorted.length; i++) first.putIfAbsent(sorted[i], i);
        for (int i = 0; i < nums.length; i++) result[i] = first.get(nums[i]);
        return result;
    }
}
```

**Key Logic:**

The first occurrence index of a value in sorted order equals the number of strictly smaller elements.

**Time Complexity:**

O(n log n) expected including map operations.

**Space Complexity:**

O(n) for sorted copy, map, and output.

### LeetCode 1331

**Question:**

Replace each array element by its rank among the distinct values: the smallest distinct value receives rank 1, equal values share a rank, and consecutive distinct values have consecutive ranks. Preserve original positions.

**Examples:**

`[40,10,20,30] → [4,1,2,3]`; `[100,100,100] → [1,1,1]`; `[37,12,28,9,100,56,80,5,12] → [5,3,4,2,8,6,7,1,3]`.

**Constraints:**

0 ≤ n ≤ 10⁵; −10⁹ ≤ arr[i] ≤ 10⁹.

**Why This Subpattern Applies:**

Dense rank transformation including ties: same sorted unique-value map but assign consecutive rank 1,2,... for each **distinct value**; O(n log n).

**Connection to Previous Solution:**

Keep sort, first-occurrence detection and map-back; replace zero-based first-position count with consecutive distinct-value rank counter.

**Java Solution:**

```java
class Solution {
    public int[] arrayRankTransform(int[] arr) {
        int[] sorted = arr.clone(), result = new int[arr.length];
        java.util.Arrays.sort(sorted);
        java.util.Map<Integer, Integer> rank = new java.util.HashMap<>();
        for (int x : sorted) if (!rank.containsKey(x)) rank.put(x, rank.size() + 1);
        for (int i = 0; i < arr.length; i++) result[i] = rank.get(arr[i]);
        return result;
    }
}
```

**Key Logic:**

Sort distinct values to construct a dense rank mapping, then project back into original order.

**Time Complexity:**

O(n log n) expected.

**Space Complexity:**

O(n) sorted copy, map, output.

### LeetCode 506

**Question:**

Athletes have distinct scores. Assign medals to the top three scores (Gold, Silver, Bronze), and for every remaining athlete assign their one-based numeric finishing position as a string. Return labels aligned with original score indices.

**Examples:**

`[5,4,3,2,1] → ["Gold Medal","Silver Medal","Bronze Medal","4","5"]`; `[10,3,8,9,4] → ["Gold Medal","5","Bronze Medal","Silver Medal","4"]`; `[100] → ["Gold Medal"]`.

```java
class Solution {
    public String[] findRelativeRanks(int[] score) {
        Integer[] order = new Integer[score.length];
        for (int i = 0; i < score.length; i++) order[i] = i;
        java.util.Arrays.sort(order, (i, j) -> Integer.compare(score[j], score[i]));

                case 0 -> "Gold Medal";
                case 1 -> "Silver Medal";
                case 2 -> "Bronze Medal";
                default -> Integer.toString(rank + 1);
            };
        }
        return result;
    }
}
```

**Key Logic:**

**Time Complexity:**

O(n log n).

**Space Complexity:**

O(n) for indices and output.

## Subpattern R5: Frequency first, comparator orders occurrences

**When to Apply:**

- Recognition: ordering is driven by **count of occurrences**, with a specified secondary tie-breaker.
- **Recognition clue:** Sort array values by increasing occurrence frequency, breaking ties by decreasing value: count frequencies then sort boxed values using two-key comparator; O(n log n).
- **Central invariant:** frequency is computed before comparison and used as a primary sort key.

**Basic Java Code Snippet:**

```java
java.util.Map<Integer,Integer> freq = new java.util.HashMap<>();
for (int x : a) freq.merge(x, 1, Integer::sum);
Integer[] boxed = java.util.Arrays.stream(a).boxed().toArray(Integer[]::new);
java.util.Arrays.sort(boxed, (x, y) -> {
    int byCount = Integer.compare(freq.get(x), freq.get(y));
    return byCount != 0 ? byCount : Integer.compare(y, x);
});
```

```java
    public int maximumGap(int[] nums) {
        int n = nums.length;
        if (n < 2) return 0;
        long min = Long.MAX_VALUE, max = Long.MIN_VALUE;
        for (int x : nums) { min = Math.min(min, x); max = Math.max(max, x); }
        if (min == max) return 0;
        long width = Math.max(1L, (max - min + n - 2) / (n - 1));
        int buckets = (int)((max - min) / width + 1);
        long[] lows = new long[buckets], highs = new long[buckets];
        boolean[] used = new boolean[buckets];
        for (int x : nums) {
            int b = (int)((x - min) / width);
            if (!used[b]) { lows[b] = highs[b] = x; used[b] = true; }
            else { lows[b] = Math.min(lows[b], x); highs[b] = Math.max(highs[b], x); }
        }
        long previous = min, best = 0;
        for (int b = 0; b < buckets; b++) {
            if (!used[b]) continue;
            best = Math.max(best, lows[b] - previous);
            previous = highs[b];
        }
        return (int)best;
    }
}
```

**Key Logic:**

```java
class Solution {
    public void wiggleSort(int[] nums) {
        int n = nums.length;
        int median = select(nums, n / 2);
        int low = 0, scan = 0, high = n - 1;
        while (scan <= high) {
            int at = mapped(scan, n);
            if (nums[at] > median) { swap(nums, mapped(low++, n), at); scan++; }
            else if (nums[at] < median) swap(nums, at, mapped(high--, n));
            else scan++;
        }
    }
    private int mapped(int i, int n) { return (1 + 2 * i) % (n | 1); }
    private int select(int[] a, int target) {
        int left = 0, right = a.length - 1;
        while (left <= right) {
            int pivot = a[java.util.concurrent.ThreadLocalRandom.current().nextInt(left, right + 1)];
            int lt = left, i = left, gt = right;
            while (i <= gt) {
                if (a[i] < pivot) swap(a, lt++, i++);
                else if (a[i] > pivot) swap(a, i, gt--);
                else i++;
            }
            if (target < lt) right = lt - 1;
            else if (target > gt) left = gt + 1;
            else return a[target];
        }
        throw new IllegalStateException();
    }
    private void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
}
```

**Key Logic:**

Select the median, then virtually reorder indices so larger-than-median values fill odd peaks and smaller values fill even valleys.

### LeetCode 2164

**Question:**

Sort values at even indices (0,2,4,...) in ascending order, and values at odd indices (1,3,5,...) in descending order. Values must remain within their original index-parity group. Return the modified array.

**Examples:**

`[4,1,2,3] → [2,3,4,1]`; `[2,1] → [2,1]`; `[9,8,7,6,5] → [5,8,7,6,9]`.

**Constraints:**

1 ≤ n ≤ 100; 1 ≤ nums[i] ≤ 100.

**Why This Subpattern Applies:**

Even-indexed values must increase, odd-indexed values must decrease: extract parity-index groups, sort each group, put values back into their original index parity positions; O(n log n) time/O(n) space.

**Connection to Previous Solution:**

Foundation of this subpattern.

**Java Solution:**

```java
class Solution {
    public int[] sortEvenOdd(int[] nums) {
        int n = nums.length;
        int[] even = new int[(n + 1) / 2], odd = new int[n / 2];
        for (int i = 0; i < n; i++) {
            if ((i & 1) == 0) even[i / 2] = nums[i];
            else odd[i / 2] = nums[i];
        }
        java.util.Arrays.sort(even);
        java.util.Arrays.sort(odd);
        for (int i = 0; i < n; i++) {
            if ((i & 1) == 0) nums[i] = even[i / 2];
            else nums[i] = odd[odd.length - 1 - i / 2];
        }
        return nums;
    }
}
```

**Key Logic:**

Index parity partitions positions into two independent sorting problems; reinsertion must respect parity.

**Time Complexity:**

O(n log n).

**Space Complexity:**

O(n) auxiliary arrays; input modified in place.

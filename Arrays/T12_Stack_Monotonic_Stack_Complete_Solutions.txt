### 01. LeetCode 20

**Problem statement (paraphrased):** Mixed bracket types: nesting and matching opener matter; `ArrayDeque<Character>` pushes openers, matches closes; O(n) time/space.

**Examples:**

1. Input: `s = "()[]{}"` → Output: `true`
2. Input: `s = "([)]"` → Output: `false`

**Constraints and important guarantees:** Parenthesis characters are drawn from `()[]{}`; reject unexpected closing types and leftovers. The full numeric bounds are maintained on the official LeetCode problem page; this workbook deliberately does not invent numeric constraints.

**Pattern recognition:** Use when nested opening/closing tokens must be checked, stripped, counted, or evaluated by depth.

**Exact evolution from previous question in this family:** **BASE:** maintain unmatched opener stack; reject mismatched/stray close and leftover open.

**Algorithm and why it works:** Store only unmatched openers; the most recent opener must match the next closer.

**Optimized Java 21 submission:**

```java
class Solution {
    public boolean isValid(String s) {
        java.util.Deque<Character> st = new java.util.ArrayDeque<>();
        for (char c : s.toCharArray()) {
            if (c == '(' || c == '[' || c == '{') st.push(c);
            else {
                if (st.isEmpty()) return false;
                char open = st.pop();
                if ((c == ')' && open != '(') || (c == ']' && open != '[')
                        || (c == '}' && open != '{')) return false;
            }
        }
        return st.isEmpty();
    }
}
```

**Complexity:** Time **O(n)**; space **O(n)**. Stack pushes/pops are amortized O(1) each; output arrays and strings are explicitly distinguished where relevant.

**Interview checkpoint:** Explain the maintained stack invariant, why a popped element cannot become relevant again, how equality is treated, and what happens on empty or all-equal inputs.

### 02. LeetCode 1021

**Problem statement (paraphrased):** Remove outermost parentheses from primitive balanced groups; depth counter emits only positions strictly inside outer depth; O(n)/O(1) auxiliary beyond output.

**Examples:**

1. Input: `s = "(()())(())"` → Output: `"()()()"`
2. Input: `s = "(()())(())(()(()))"` → Output: `"()()()()(())"`

**Constraints and important guarantees:** `s` is a valid nonempty parentheses sequence split into primitives. The full numeric bounds are maintained on the official LeetCode problem page; this workbook deliberately does not invent numeric constraints.

**Pattern recognition:** Use when nested opening/closing tokens must be checked, stripped, counted, or evaluated by depth.

**Exact evolution from previous question in this family:** Specialize matched-parentheses invariant to one bracket type; replace opener stack with numeric depth and conditional output on open/close.

**Algorithm and why it works:** Increment depth on `(` and decrement on `)`; emit only characters whose depth is internal to a primitive.

**Optimized Java 21 submission:**

```java
class Solution {
    public String removeOuterParentheses(String s) {
        StringBuilder out = new StringBuilder(); int depth = 0;
        for (char c : s.toCharArray()) {
            if (c == '(') { if (depth > 0) out.append(c); depth++; }
            else { depth--; if (depth > 0) out.append(c); }
        }
        return out.toString();
    }
}
```

**Complexity:** Time **O(n)**; space **O(1) auxiliary; O(n) output**. Stack pushes/pops are amortized O(1) each; output arrays and strings are explicitly distinguished where relevant.

### 04. LeetCode 856

**Problem statement (paraphrased):** Evaluate nested parentheses score: primitive pair contributes 1, wrapping doubles, concatenation adds; use score stack per open parenthesis; O(n) time/space.

**Examples:**

1. Input: `s = "()"` → Output: `1`
2. Input: `s = "(()(()))"` → Output: `6`

**Pattern recognition:** Use when nested opening/closing tokens must be checked, stripped, counted, or evaluated by depth.

**Exact evolution from previous question in this family:** Replace max-depth aggregation with per-level score frames; on close combine `max(2*inner,1)` with parent score.

**Algorithm and why it works:** Each open starts a zero-score child; closing adds 1 for `()` or twice the child score.

**Optimized Java 21 submission:**

```java
class Solution {
    public int scoreOfParentheses(String s) {
        java.util.Deque<Integer> st = new java.util.ArrayDeque<>();
        int score = 0;
        for (char c : s.toCharArray()) {
            if (c == '(') { st.push(score); score = 0; }
            else score = st.pop() + Math.max(1, 2 * score);
        }
        return score;
    }
}
```

### 06. LeetCode 1249

**Problem statement (paraphrased):** Remove minimal parentheses and preserve all letters; mark unmatched closes in forward pass and unmatched opens via stack/backward pass; build filtered result.

**Examples:**

1. Input: `s = "lee(t(c)o)de)"` → Output: `"lee(t(c)o)de"`
2. Input: `s = "a)b(c)d"` → Output: `"ab(c)d"`

**Constraints and important guarantees:** `s` includes lowercase letters and parentheses; any minimum-removal valid result is accepted. The full numeric bounds are maintained on the official LeetCode problem page; this workbook deliberately does not invent numeric constraints.

**Pattern recognition:** Use when invalid parentheses must be counted, removed, or repaired under explicit pairing rules.

**Exact evolution from previous question in this family:** Change repair counting into index marking and reconstruction; preserve validity invariant but return corrected string.

**Algorithm and why it works:** Mark unmatched closing indices as they arrive and unmatched opening indices left on the stack.

**Optimized Java 21 submission:**

```java
class Solution {
    public String minRemoveToMakeValid(String s) {
        boolean[] remove = new boolean[s.length()];
        java.util.Deque<Integer> open = new java.util.ArrayDeque<>();
        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            if (c == '(') open.push(i);
            else if (c == ')') {
                if (open.isEmpty()) remove[i] = true;
                else open.pop();
            }
        }
        while (!open.isEmpty()) remove[open.pop()] = true;
        StringBuilder out = new StringBuilder();
        for (int i = 0; i < s.length(); i++) if (!remove[i]) out.append(s.charAt(i));
        return out.toString();
    }
}
```

**Complexity:** Time **O(n)**; space **O(n)**. Stack pushes/pops are amortized O(1) each; output arrays and strings are explicitly distinguished where relevant.

**Exact evolution from previous question in this family:** Replace ordinary one-close pairing with two-close grammar and adjust odd pending-close requirement; accumulate insertions.

**Algorithm and why it works:** `need` tracks how many closing characters are still owed; odd demand before `(` requires one insertion.

**Optimized Java 21 submission:**

```java
class Solution {
    public int minInsertions(String s) {
        int need = 0, edits = 0;
        for (char c : s.toCharArray()) {
            if (c == '(') {
                if ((need & 1) != 0) { edits++; need--; }
                need += 2;
            } else {
                need--;
                if (need < 0) { edits++; need = 1; }
            }
        }
        return edits + need;
    }
}
```

### 11. LeetCode 1209

**Problem statement (paraphrased):** Delete adjacent groups when run reaches k; store (character,runCount), increase top count or push new run, pop at k.

**Examples:**

**Pattern recognition:** Use when an incoming symbol may annihilate the latest retained symbol, possibly using counts.

**Exact evolution from previous question in this family:** Generalize top symbol into (symbol,count) run frames; pop only when count reaches k instead of cancelling immediately.

**Algorithm and why it works:** Store a count for each currently surviving run and remove it exactly when count reaches `k`.

**Optimized Java 21 submission:**

```java
class Solution {
    public String removeDuplicates(String s, int k) {
        char[] chars = new char[s.length()];
        int[] counts = new int[s.length()]; int size = 0;
        for (char c : s.toCharArray()) {
            if (size > 0 && chars[size - 1] == c) {
                if (++counts[size - 1] == k) size--;
            } else { chars[size] = c; counts[size] = 1; size++; }
        }
        StringBuilder out = new StringBuilder();
        for (int i = 0; i < size; i++) out.append(String.valueOf(chars[i]).repeat(counts[i]));
        return out.toString();
    }
}
```

**Exact evolution from previous question in this family:** Reuse minimum contribution counts; add symmetric maximum contribution using decreasing stack and subtract totals.

**Algorithm and why it works:** Use matched tie-breaking for all-subarray maximum contributions and minimum contributions, then subtract.

**Optimized Java 21 submission:**

```java
class Solution {
    public long subArrayRanges(int[] nums) {
        return contribution(nums, true) - contribution(nums, false);
    }
    private long contribution(int[] a, boolean max) {
        java.util.Deque<Integer> st = new java.util.ArrayDeque<>(); long sum = 0;
        for (int right = 0; right <= a.length; right++) {
            while (!st.isEmpty() && (right == a.length ||
                    (max ? a[st.peek()] <= a[right] : a[st.peek()] >= a[right]))) {

            }
            st.push(right);
        }
        return sum;
    }
}
```

### 36. LeetCode 2281

**Problem statement (paraphrased):** Sum minimum × sum of each subarray; keep minimum contribution boundaries, add prefix-of-prefix sums for weighted sum of all intervals assigned to each minimum; O(n).

**Examples:**

1. Input: `strength=[1,3,1,2]` → Output: `44`
2. Input: `strength=[5,4,6]` → Output: `213`

**Constraints and important guarantees:** Strength values are positive; output is modulo 1,000,000,007. The full numeric bounds are maintained on the official LeetCode problem page; this workbook deliberately does not invent numeric constraints.

**Pattern recognition:** Use when aggregating minima/maxima over ALL subarrays without enumerating them.

**Exact evolution from previous question in this family:** Return to minimum ownership spans; replace plain interval-count factor with weighted interval-sum formula from double prefix sums.

**Algorithm and why it works:** Minimum-owned ranges remain; double prefix sums aggregate sums of every interval assigned to each minimum.

**Optimized Java 21 submission:**

```java
class Solution {
    public int totalStrength(int[] strength) {
        final long MOD = 1_000_000_007L;
        int n = strength.length;
        long[] p = new long[n + 1], pp = new long[n + 2];
        for (int i = 0; i < n; i++) p[i + 1] = (p[i] + strength[i]) % MOD;
        for (int i = 0; i <= n; i++) pp[i + 1] = (pp[i] + p[i]) % MOD;
        int[] left = new int[n], right = new int[n];
        java.util.Deque<Integer> st = new java.util.ArrayDeque<>();
        for (int i = 0; i < n; i++) {
            while (!st.isEmpty() && strength[st.peek()] >= strength[i]) st.pop();
            left[i] = st.isEmpty() ? -1 : st.peek(); st.push(i);
        }
        st.clear();
        for (int i = n - 1; i >= 0; i--) {
            while (!st.isEmpty() && strength[st.peek()] > strength[i]) st.pop();
            right[i] = st.isEmpty() ? n : st.peek(); st.push(i);
        }
        long answer = 0;
        for (int i = 0; i < n; i++) {
            int l = left[i], r = right[i];
            long rightSum = (pp[r + 1] - pp[i + 1] + MOD) % MOD;
            long leftSum = (pp[i + 1] - pp[l + 1] + MOD) % MOD;
            long weighted = (rightSum * (i - l) % MOD - leftSum * (r - i) % MOD + MOD) % MOD;
            answer = (answer + strength[i] * weighted) % MOD;
        }
        return (int)answer;
    }
}
```
